01 / 问题

为什么要把「智能体、推理、代码」拧成一股绳？

大模型正从「知识库」进化为「通用问题求解器」。但作者认为，要衡量一个模型是否真正通用，关键看三类彼此交织的核心能力——而过去这三件事往往被分开优化、互相牵制。

论文开门见山地把这三类能力定义为模型走向 AGI 的「试金石」：

  • Agentic（智能体能力）：能调用外部工具、与真实世界环境交互，比如多轮函数调用、网页浏览检索。
  • Reasoning（复杂推理）：能在数学、科学等领域完成多步推导，答案可被客观验证。
  • Coding（代码能力）：能解决真实软件工程任务，比如读懂一个仓库、修复 GitHub issue。
"Agentic abilities for interacting with external tools and the real world; complex Reasoning for solving multi-step problems… and advanced Coding skills for tackling real-world software engineering tasks." 这三类能力（ARC）相互关联、缺一不可，是「真正通才」的度量标准。

已有方案卡在哪里

最强的闭源模型（OpenAI o1/o3、Anthropic Claude Sonnet 4）确实在某一个 ARC 维度上很突出——要么擅长数学推理，要么擅长改代码。但论文指出：一个在三方面同时出色的开源模型，一直是缺失的（remained elusive）。开源阵营要么偏科，要么靠堆参数取胜，参数效率不高。

GLM-4.5 给出的答案不是「再训一个更大的模型」，而是从架构、数据到训练范式都围绕「ARC 统一」来设计：用一个混合推理（hybrid reasoning）的 MoE 模型，既能「想清楚再答」，也能「即时回复」，并通过「先分头训练专家、再蒸馏融合」的方式把三种能力装进同一套权重。下面按论文自身的结构展开：预训练 → 后训练 → RL 基建 → 实验。

名词卡 · 什么是混合推理（Hybrid Reasoning）？ 同一个模型提供两档「思考力度」：thinking 模式会先输出一段 <think>…</think> 推理再作答，适合难题与工具调用；non-thinking 模式跳过思考直接回答，适合闲聊等需要低延迟的场景。关键挑战是让同一套权重学会两种模式，这正是后训练阶段要解决的问题。
02 / 预训练 & 中训练

底座怎么搭：窄而深的 MoE，加上「分阶段加料」的训练

架构：故意「窄而深」，并堆更多注意力头

GLM-4.5 系列首次采用 MoE（混合专家）架构来提升训练与推理的计算效率，并使用 loss-free balance routing（无损均衡路由）和 sigmoid 门控。和 DeepSeek-V3、Kimi K2 不同，作者做了几个有意思的反直觉选择：

  • 窄而深，而不是宽而浅。主动减小宽度（隐藏维度、路由专家数）、增加深度（层数），因为他们发现更深的模型推理能力更强。
  • 2.5 倍的注意力头。在 5120 的隐藏维度上用了 96 个注意力头。反直觉的是：更多的头并不降低训练 loss，却能持续提升 MMLU、BBH 等推理基准的表现。
  • 注意力细节：采用 分组查询注意力（GQA）+ 部分 RoPE，并加入 QK-Norm 稳定注意力 logits 的数值范围。
  • MTP 层：为 GLM-4.5 和 Air 都加了一层 多 token 预测（MTP），用于推理时的投机解码（speculative decoding）加速。
"we reduce the width… and increase its height (number of layers), as we found that deeper models exhibited better reasoning capacity." 减宽增深——因为更深的模型展现出更强的推理能力。这是 GLM-4.5 架构选择的核心直觉。

数据：按来源分别清洗，按质量分桶上采样

预训练语料来自网页、社交媒体、书籍、论文和代码仓库，每类来源都有专门的处理流程：

  • 网页（占大头）：借鉴 Nemotron-CC，按质量分数分桶，高质量桶上采样、最低质量桶丢弃；最高质量桶在预训练中贡献 3.2+ 个 epoch。还用 SemDedup（基于文档向量）去掉 MinHash 去重漏掉的「模板批量生成」的相似网页。
  • 代码：分高/中/低三档质量，高质量上采样、低质量剔除；对所有源码施加 Fill-In-the-Middle（中间填空）训练目标；对代码相关网页做两阶段检索 + 精细解析以保留代码格式。
  • 多语言：结合自爬网页与 Fineweb-2，用「教育价值」质量分类器上采样高质量多语文档。
  • 数学 & 科学：用 LLM 按「教育性内容比例」给候选文档打分并训练小分类器，高分文档上采样，专门增强推理底子。

中训练（Mid-Training）：在底座上「定向加料」

预训练之后，作者没有直接进入后训练，而是插入若干 中训练（mid-training）阶段——用中等规模、领域专门的数据集（含指令数据）进一步拔高关键能力，并把序列长度从 4K 一路扩到 128K：

  • 仓库级代码训练：把同一仓库的代码文件拼接，学习跨文件依赖；还纳入经过筛选的 GitHub issue / PR / commit（以 diff 格式组织）。序列长度 4K → 32K。
  • 合成推理数据训练：收集数学、科学、编程竞赛的问答，用推理模型合成推理过程。
  • 长上下文 & 智能体训练：序列长度 32K → 128K，上采样长文档，并引入大规模合成智能体轨迹。

训练超参里的几个关键选择

  • Muon 优化器（替代 AdamW，用于除词嵌入/bias/RMSNorm 外的所有参数）：能加速收敛、容忍更大 batch。
  • 用 cosine 衰减而非 WSD 调度。早期实验发现 WSD（warmup-stable-decay）在稳定期欠拟合，通用基准（SimpleQA、MMLU）反而更差。学习率从 0 warmup 到 2.5e-4，再衰减到 2.5e-5。
  • batch size warmup：前 500B tokens 内从 16M 逐步增到 64M tokens。
  • 扩长上下文时调 RoPE：扩到 32K 时把 RoPE base 频率从 10,000 调到 1,000,000，改善长上下文建模。
03 / 后训练 · 核心贡献

专家模型迭代：先「分头练专家」，再「蒸馏成通才」

这是 GLM-4.5 把 ARC 三种能力装进同一套权重的关键。后训练被拆成两个阶段：先训出各有所长的专家模型，再把它们融合成一个混合推理通才。

  • 阶段一 · 专家训练（Expert Training）：分别构建 推理（Reasoning）、智能体（Agent）、通用对话（General chat）三个专家模型。每个专家先用 SFT 做冷启动，再用各自领域的 RL 把能力推到上限。
  • 阶段二 · 统一训练（Unified Training）：用自蒸馏（self-distillation）把多个专家的能力整合进一个模型，最终得到既能「深思」又能「直答」的混合推理通才。

SFT 阶段的几个实用技巧

  • 冷启动 + Overall SFT：冷启动用少量长 CoT 数据给每个专家打底；Overall SFT 则从各专家收集数百万样本（推理、通用对话、智能体、长上下文），在 128K 上下文下训练，并刻意平衡「带完整推理」与「不带思考过程」的数据，从而炼成混合推理模型。
  • 函数调用模板减少转义：当函数参数里含代码时，JSON 格式会逼模型生成大量转义字符、加重学习负担。作者改用 XML 风格的特殊 token 标签包裹键值，让绝大多数代码能以原生形式书写——既减少转义，又不损害函数调用的执行性能。
  • 拒绝采样多级过滤：从专家采样时，过滤掉重复/过短/截断/格式不合规的样本，对客观题做正确性校验，对主观题用奖励模型筛选，对工具调用校验是否到达预期终止状态。
  • 难 prompt 优先 + 回答扩增：去掉「回答长度最短 50%」的简单 prompt，数学/科学反而提升 2%–4%（数据只用一半）；对这些难 prompt 每条生成 4 个回答，再额外提升 1%–2%。
  • 智能体 SFT 数据全自动构造（四步）：① 收集智能体框架与真实工具 / MCP server；② 自动合成任务；③ 用 LLM（含用户模拟器）生成多轮工具调用轨迹；④ 多个评审 agent 过滤，只保留成功轨迹。

04 / 强化学习

RL：把推理、智能体、通用三条线分别顶到上限

GLM-4.5 的 RL 整体基于 GRPO 框架（去掉 KL 损失项）。论文按能力类型把 RL 拆成三块，每块都有针对性的「踩坑经验」。注意：以下许多对比曲线来自更小的实验模型，便于快速消融。

推理 RL（Reasoning RL）

推理任务的特点是奖励信号高度精确——对错往往能用程序客观判定。作者发展了一套专门技巧：

  • 两阶段难度课程（Difficulty-based Curriculum）：RL 中模型能力在变，静态数据会失配——太简单全得 1 分、太难全得 0 分，都没有奖励方差、没有梯度信号。于是先用中等难度数据，第二阶段切到「极难」题（pass@8=0 但 pass@512>0），让模型持续突破天花板。第二阶段题目全部来自已验证正确答案的池子以保证信噪比。
  • 直接在 64K 输出长度做单阶段 RL：与「逐步增大输出长度」的多阶段做法相反，作者发现多阶段会让模型「遗忘」长上下文能力、平均输出变短，造成不可逆的性能下跌；直接在目标长度 64K 上做单阶段 RL 反而持续向上。
  • 动态采样温度：温度太低探索不足、太高引入噪声。当奖励趋于稳定（进入收敛期）时提高温度鼓励多样性；并定期在验证集上跨温度评测，把下一阶段温度设为「不会让性能下跌超过 1%」的最大值。
  • 代码 RL 用 token 加权平均损失：相比序列平均损失，token 加权能给出更细粒度、更稳定的梯度，收敛更快，还能缓解长度偏置、抑制「base case」式偷懒回答。
  • 科学 RL 数据质量压倒数量：在 GPQA-Diamond 上，只用专家验证过的高质量选择题训练，明显优于混入低质量/未验证数据。
直觉卡 · 为什么「全对」和「全错」都是坏事？ GRPO 这类方法靠「同一题的多个回答之间的奖励差异」来更新模型。如果一批回答全得满分或全得零分，组内没有高下之分，梯度信号≈0，训练就「空转」。难度课程的本质，就是始终把模型放在「会一点、又不全会」的甜区。

智能体 RL（Agentic RL）

作者把重心放在网页搜索与代码生成两类智能体上，因为它们的每一步动作或最终答案都能自动校验，从而提供密集可靠的奖励，便于把 RL 规模做大。

  • 数据合成：网页搜索任务用「知识图谱多跳推理自动合成」+「人在环路抽取并选择性混淆网页内容」两条路构造需要多源多步推理的难题；软件工程任务则从大量 GitHub PR / issue 构造「带可执行单测」的真实开发任务，并在强隔离的分布式沙箱里评测。
  • 奖励设计：网页搜索用最终答案准确率作为整条轨迹的奖励；代码 agent 主要用带可验证测试用例的 SWE 数据。额外加「过程动作格式惩罚」：一旦工具调用格式出错，立即中止该轨迹并给 0 奖励。
  • 迭代自蒸馏：智能体 RL 很耗时，于是先 RL 提升、达到平台期后用 RL 模型的回答替换冷启动数据得到更强的 SFT 模型，再继续 RL 并逐步加难——循环往复地推高上限。
  • 用交互轮数做测试时扩展：不同于推理模型「拉长输出 token」，智能体靠持续与环境交互（反复搜索、写测试自检自纠）来使用更多测试时算力；论文显示随浏览预算增加，BrowseComp 准确率平滑上升。

通用 RL（General RL）

作为后训练的收尾，通用 RL 用多源反馈整体打磨：规则反馈（精确）、人类反馈 RLHF（细腻判断）、模型反馈 RLAIF（可扩展）三者融合。它包含：

  • Holistic RL（全面 RL）：构建约 5,000 条覆盖 7 大类 / 33 中类 / 139 小类的均衡 prompt 集，奖励来自人类偏好奖励模型 + 模型打分。
  • 指令遵循 RL：建立 7 大类 / 151 小类的约束分类法，用「确定性规则 + 奖励模型 + 批评模型」的混合反馈对抗 reward hacking；约 1,000 步内未见明显作弊，SysBench 稳步提升。
  • 函数调用 RL：分为分步规则 RL（每步比对 ground-truth 函数调用，名称 / 参数 / 字段完全匹配且格式正确才给 1 分）与端到端多轮 RL（先生成完整轨迹，再按任务是否完成给奖励，支持单轮多步 / 多轮多步任务）。
  • Pathology RL（病态行为 RL）：专门针对语言混杂、过度重复、格式错误等低发生率（常<1% 输出）问题，挑选最易触发的 prompt 做高效惩罚，压低残余错误率。
▸ 展开：智能体 RL 的目标函数与「只优化模型生成 token」公式

对每个问题 x，从旧策略采样 K 条轨迹，按「相对组内平均奖励」的优势来优化（组级策略优化）：

L_RL(θ) = E_{x~D} [ (1/K) Σ_i ( r(x, y_i) − r̄(x) ) ]
其中 r̄(x) = (1/K) Σ_i r(x, y_i)  // 组内平均奖励

关键细节：只有模型生成的 token 参与优化，环境反馈（工具返回内容）不计入损失——避免模型去「拟合」自己无法控制的环境输出。

05 / RL 基础设施

slime：让长程智能体 RL 不再「卡在最慢的那条轨迹」

大规模智能体 RL 的最大瓶颈是数据生成（rollout）效率：智能体要和复杂环境长时间交互，轨迹长短不一，同步训练时整条流水线会被最慢的 rollout 拖死。GLM-4.5 的 RL 跑在自研开源框架 slime（THUDM/slime）上。

三个关键工程设计

  • 同步 / 异步两种模式可切换：推理类任务（数学、代码）用同机同步模式 + 动态采样，最大化 GPU 利用率；智能体任务（如 SWE）数据生成慢、交互复杂，改用分离式异步模式——rollout 引擎直接对接 agent 环境，与训练 GPU 独立调度，不被训练周期拖停。
  • 混合精度 rollout：训练用 BF16，推理 rollout 用 FP8——每次策略更新前对参数做在线、分块 FP8 量化，显著提升数据收集吞吐。
  • 面向 agent 的解耦设计：用高并发 Docker 为每个任务提供隔离环境；用统一 HTTP 端点 + 中心化数据池把「各式各样的 agent 框架」与训练过程解耦——大多数框架输出 message-list 格式，统一存入数据池供训练取用，从而无缝接入异构 agent 框架。
06 / 实验结论

用「一半的参数」打进第一梯队

在覆盖 ARC 三类能力的 12 个标准基准上，GLM-4.5 综合排名第 3（仅次于头部闭源模型），智能体任务第 2（仅次于 OpenAI o3），代码任务第 3（紧追 Claude Sonnet 4）；GLM-4.5-Air 综合第 6。而它的参数量只有 DeepSeek-R1 的一半、Kimi K2 的三分之一。

分项亮点（均来自论文表 3–5）：

  • 智能体：TAU-Bench 与 Claude Sonnet 4 同档，优于 Gemini 2.5 Pro；BFCL v3 取得基线中最佳；BrowseComp 26.4% 明显高于 Claude Opus 4（18.8%）、接近 o4-mini-high。
  • 推理：AIME 24（91.0%）与 SciCode 上超过 OpenAI o3；平均推理表现超过 Claude Opus 4、接近 DeepSeek-R1-0528。
  • 代码：SWE-bench Verified 上优于 GPT-4.1 与 Gemini-2.5-Pro；Terminal-Bench 上优于 Claude Sonnet 4；综合是 Claude Sonnet 4 在代码上最有力的竞争者。
  • 真实编程对战（CC-Bench）：对 Qwen3-Coder 80.8% 胜率，对 Kimi K2 53.9% 胜率，对 Claude Sonnet 4 互有胜负；工具调用成功率 90.6% 为参评最高。

一句话结论

"GLM-4.5 excels at reasoning, coding, and agentic tasks, ranked in 3rd place globally among open-source and proprietary models." GLM-4.5 在推理、代码、智能体三类任务上俱佳，在所有开源与闭源模型中综合排名第 3——并以开源、参数高效的姿态证明了「ARC 统一」这条路走得通。
综合排名 第 3 智能体 第 2 参数效率 ≈DeepSeek-R1 的 1/2 开源 MIT 轻量版 GLM-4.5-Air 106B
