01 问题：会推理不难，难的是「稳、强、可复现」

过去一年，靠大规模强化学习训练的推理模型（OpenAI o1、DeepSeek R1、Gemini 2.5、Claude 3.7）突飞猛进。但要自己训出一个对标它们的模型，会撞上三堵墙：

  • 方法被「藏」起来了：支撑可扩展 RL 训练的核心方法与算法，大多没有写进各家技术报告，社区难以复现。
  • RL 训练极不稳定：推理模型的 RL 训练经常崩溃，尤其是没有 SFT 的情况下；论文坦言两次训练的分数能差到 10 分。稳定性才是成败关键。
  • 连「尺子」都不够用了：大家常用的 AIME 每年只有 30 道题，方差太大，已经区分不开顶尖模型。
本文要回答的问题
如何把易崩的 RL 训练做得稳定可靠，并把它系统性地讲清楚（数据怎么造、奖励怎么给、算法怎么稳、系统怎么快），最终在一个不算大的 MoE 上练出对标顶尖闭源模型的推理能力——同时再造一把更精准的「尺子」。

02 方法总览：一套训练流水线，三根支柱

整篇论文可以收敛成一条流水线和三根支柱。流水线是：先 SFT 冷启动，再 大规模 RL，得到 Seed-Thinking-v1.5；而支撑这条流水线跑通、跑稳、跑快的，是数据、算法、基础设施这三根支柱。

支柱① 数据 学什么
SFT 依赖长思维链（CoT）数据；RL 融合四类数据——STEM、代码、逻辑推理、非推理（创作/对话）。其中数学数据泛化能力极强，能带动各项任务一起涨；逻辑题则显著拉高 ARC-AGI。
支柱② RL 算法 怎么稳着学
首创 VAPO（value-based）与 DAPO（value-free）两套框架，分别是各自范式下的 SOTA，专门针对 RL 训练的不稳定性，给出稳定、一致的训练轨迹。
支柱③ RL 基础设施 能多快地学
用流式 Rollout 系统（SRS）异步处理「半成品」生成轨迹，迭代速度比同步框架快 3 倍；并支持混合精度训练与自动故障恢复。

03 数据：可验证的「硬」题 + 不可验证的「软」题

RL 训练数据分两大类：有标准答案（verifiable）和没有标准答案（non-verifiable）。模型的推理能力主要来自前者，并能泛化到后者。

🔬STEM 数据 ~10 万题
竞赛级数学/物理/化学题（数学占 80%+），经严格清洗与增强。
展开说明 ▸

清洗：删除表述不清的题；用 Doubao-Pro 1.5 多次作答，「最差 N 次都对」(woN=1) 的太简单题被剔除；再用 SOTA 模型交叉验证、人工复核参考答案是否正确。

增强：把选择题改成填空/简答杜绝瞎猜，并尽量把答案改成整数，便于稳定判分。训练时用 Seed-Verifier 判对错。

💻代码数据 竞赛 + 沙箱
来自高质量算法竞赛题，每题配「描述 + 单元测试 + checker 脚本」。
展开说明 ▸

评测：RL 中无法实时提交官方平台，于是自建离线评测集 + 内部代码沙箱，直接执行模型代码；离线结果与官方判定高度相关。

关键：沙箱要稳定、高吞吐，才能在 RL 中持续给出准确反馈。

🧩逻辑谜题 22 类 · ~1 万题
24 点、迷宫、数独等 22 种常见任务，每类配生成器 + 答案验证器。
展开说明 ▸

可控难度：生成器能自动造大量训练/评测数据，并根据模型表现动态调难度（课程式）。验证器可直接当 RL 的奖励函数。

效果：逻辑数据对 ARC-AGI 基准提升显著（Seed 39.9% vs R1 18.3%）。

✍️不可验证数据 人类偏好
创作、翻译、知识问答、角色扮演等，靠人类偏好打分。
展开说明 ▸

筛选：用 SFT 模型对每个 prompt 采样多个候选并用奖励模型打分，剔除分数方差太低、太简单的样本（这类题过度优化会让探索空间过早坍缩）。

打分：采用成对（pairwise）比较奖励，让模型更好理解用户偏好。prompt 源自 Doubao-1.5 Pro 的 RL 数据。

🆕 顺手造了一把更准的尺子：BeyondAIME
因为 AIME 每年只有 30 题、区分度不够，作者与数学专家合作原创了 100 道题，难度≥AIME 最难题，答案保证为整数、且绝不取题面里出现过的平凡值（防止瞎猜）。BeyondAIME 与内部 Codeforces 评测集都将公开发布。

04 奖励建模：让「裁判」自己也会思考

奖励是 RL 的指挥棒。本文没有用简单的字符串匹配规则，而是用 LLM 当裁判，并设计了两代递进式验证器来判断「可验证题」的答案对不对。

第一代：Seed-Verifier
  • 基于人工精心编写的原则 + LLM 基础能力
  • 输入「题目 + 参考答案 + 模型答案」三元组，判断是否本质等价，返回 YES / NO
  • 不是字面精确匹配，而是按数学规则判等价
  • 问题：遇到 2^19 vs 524288 这类等价表达时，有时 YES 有时 NO（不稳定）
第二代：Seed-Thinking-Verifier
  • 模仿人类判卷：先详细推理、再下结论
  • 把「判分」本身当作一个可验证任务来训练（与数学推理一起优化）
  • 能逐项剖析参考答案与模型答案的异同
  • 同时缓解三大顽疾：奖励作弊、判断不一致、边角案例失败

06 RL 工具箱：六个让训练「稳下来」的关键技巧

长 CoT 的 RLHF 容易被两件事拖垮：价值模型有偏、奖励信号稀疏。本文借鉴前作（VAPO/DAPO 等）凝练出一套技巧，逐一对症下药：

🎯Value-Pretraining
先让价值模型与 SFT 策略「对齐」，再开始 RL。
展开说明 ▸

用固定策略（如 π_sft）采样，再用蒙特卡洛回报更新价值模型，使初始化的 value model 与策略完全对齐。

这对保住模型的 CoT 模式至关重要，能让它生成连贯、有逻辑的思维链。

🔀Decoupled-GAE
价值与策略用不同的 GAE 参数，互不拖累。
展开说明 ▸

设 λ_value = 1.0（让价值无偏更新）、λ_policy = 0.95（让策略独立平衡偏差与方差）。

解耦之后，两边各取所需，训练更高效、更稳定。

📏Length-adaptive GAE
按回复长度自适应调 λ，长短序列一视同仁。
展开说明 ▸

令 λ_policy = 1 − 1/(α·l)，其中 l 是回复长度。

这样能让 TD 误差在长、短序列上分布更均匀，模型处理不同长度的序列时更稳。

⬆️Clip-Higher
把 PPO 的上下裁剪边界解耦，给低概率 token 更多空间。
展开说明 ▸

把裁剪写成 clip(r, 1−ε_low, 1+ε_high)，调高 ε_high，给低概率 token 的概率上升留出空间。

效果：鼓励探索更广的回答空间，更容易发现新颖有效的解法（来自 DAPO）。

🔤Token-level Loss
损失定义在「每个 token」而非「整条回复」上。
展开说明 ▸

按 token 而非整句计算策略损失，纠正不同长度回复对总损失贡献失衡的问题。

确保每个 token 对训练的影响都被恰当计入，长回复不会被「稀释」。

➕Positive Example LM Loss
给正样本额外加一项语言模型损失，提高利用率。
展开说明 ▸

总损失 = L_PPO + μ · L_NLL，对正样本额外加一项带系数 μ 的 NLL（语言模型）损失。

目的：提升正样本的利用效率，让模型更充分地从「答对的样例」里学习。

L(θ) = LPPO(θ) + μ · LNLL(θ)
正样本语言模型损失：在标准 PPO 损失之外，对答对的样例再加一项 NLL 损失，提升正样本利用率。

07 VAPO 与 DAPO：两条稳定 RL 的技术路线

上面的技巧分别归属于两套框架。本文首创这两套框架，分别拿下「价值法」与「无价值法」两个范式的 SOTA：

VAPO · value-based（有价值模型）
  • 依赖一个价值网络（critic）来估计优势
  • 用上 value 预训练、解耦 GAE、长度自适应 GAE 等技巧驯服价值偏差
  • 价值法范式下的 SOTA
DAPO · value-free（无价值模型）
  • 不用价值网络，靠 Clip-Higher、Token-level Loss、动态采样等稳住训练
  • 更轻量，适合大规模扩展
  • 无价值法范式下的新 SOTA

论文做了一个很实用的观察：RL 算法的优劣排序在不同规模、不同架构的模型上是一致的。这意味着可以用小模型（Qwen-32B）当「代理模型（proxy）」来研究 RL 算法，省下大量算力：

Qwen-32B-Dense（稠密）50%60%
Seed-150B-MoE73%79%

两种模型上 VAPO > DAPO 的排序一致（节选自原论文 Table 4；Seed-150B-MoE 为有限步数的消融实验结果）。说明 Qwen-32B 可作为研究 RL 算法的可靠代理。

08 基础设施：用「流式 Rollout」把训练加速 3 倍

RL 训练里最耗时的环节之一是 rollout（让模型生成回答）：一个 batch 里有的回答短、几百 token 就完事，有的长、要上万 token，同步等待最慢的那个会浪费大量算力。流式 Rollout 系统（SRS）的做法是不等了：

① 最新模型
用最新版本模型生成一部分样本（on-policy，占比 α）。
+
② 历史快照续写
剩下没生成完的部分（1−α）交给历史版本快照异步续写（off-policy）。
→
③ 优先级样本池
on-policy 片段α
off-policy 续写1−α
→
④ 训练 → 更新
合并后训练并更新模型，再回到 ①。on/off-policy 比例由 α 动态调节。
图 B（本导读自制 · 依据原文文字）：流式 Rollout 系统（SRS）将「模型演化」与「运行时执行」解耦，用完成率 α 动态混合 on/off-policy 样本，迭代速度比同步框架快 3 倍。
展开说明 ▸
  • 上路（实线）：最新模型负责 on-policy 生成，占比为完成率 α ∈ [0,1]——即用最新模型现场生成的样本比例。
  • 下路（实线）：剩下「没生成完」的片段（1−α）交给历史版本快照，在独立资源上异步续写（off-policy），不让整个 batch 卡在最慢的长序列上。
  • 中间「优先级样本池」：把 on/off-policy 的部分轨迹异步汇聚起来，解耦模型演化与运行时执行。
  • 右侧「训练/更新」：合并样本训练并更新模型；虚线闭环表示更新后的模型回到 on-policy 端继续生成，形成持续迭代。
  • 一句话总结：通过「不等慢序列、异步续写、动态调 α」，SRS 把 RL 迭代周期压到同步框架的 1/3。此外还配合 FP8 rollout、TP/EP/SP 三级并行、KARP 序列均衡、AutoTuner、ByteCheckpoint 等系统优化。

09 实验结论：小身材，大能量

10 有意思的点

除了分数，几处设计取舍与发现更能帮你判断这套方法适不适合自己的场景：

⚖️稳定性才是真瓶颈
论文罕见地承认 RL 训练「两次跑能差 10 分」。
展开说明 ▸

很多报告只报最好成绩，本文却把不稳定、易崩当成头号敌人来攻。VAPO/DAPO 和整套技巧的价值，正是把方差压下来、让结果可复现。

启发：复现推理 RL 时，先解决稳定性，再谈刷分。

🧠会思考的裁判更准
让验证器自己也走一遍 CoT，准确率从 82.7% 跳到 99.3%。
展开说明 ▸

把「判分」当成可验证任务去训练（Seed-Thinking-Verifier），不仅更准，还能抗奖励作弊、给一致判断、handle 边角案例。

代价：思考要花大量 GPU，但作者认为精准奖励对练强推理「值这个价」。

🌐数学训练会「外溢」
GPQA（科学）的提升主要来自数学训练的泛化，而非加科学数据。
展开说明 ▸

论文明确指出：数学数据泛化能力极强，能带动多项任务一起涨；而逻辑谜题显著拉高 ARC-AGI。

言下之意：练好「硬核可验证推理」，能力会向更广的领域迁移。

🔬小模型可当算法「代理」
RL 算法排序在不同规模/架构上一致，Qwen-32B 可代理实验。
展开说明 ▸

VAPO > DAPO 的排序在 Qwen-32B-Dense 与 Seed-150B-MoE 上一致，说明可用小模型省算力地做 RL 算法探索。

另一反直觉发现：RFT 初始化前期更快、最终更低（58% → 54%），热身别过头。

11 局限与未来方向

论文对短板也比较坦诚，这些往往比成绩单更能帮你判断它适不适合你的场景：

  • 对最强模型仍有差距：在 BeyondAIME、AIME 2025、Codeforces、SWE-bench 等更难/更工程化的集合上，落后于 o3-level 与 Gemini 2.5 Pro。
  • 事实记忆偏弱：SimpleQA 仅 12.9，但这是记忆导向指标，更看预训练规模，并非真实推理能力的体现。
  • 奖励建模成本高：会思考的验证器虽准，却要消耗大量 GPU。
  • 未来方向：探索更高效的 RL 配方、挑战更难的思考任务，以及做出精度可比验证器的通用奖励模型。
这篇论文最值得记住的一句话
训练顶尖推理模型不是靠某一个神奇技巧，而是把数据、RL 算法、RL 基础设施三件事同时做扎实——尤其是先把「易崩的 RL」训稳，剩下的分数才谈得上。
