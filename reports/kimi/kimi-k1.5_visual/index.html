Kimi k1.5：用「长上下文」把强化学习扩展到大模型

Kimi k1.5: Scaling Reinforcement Learning with LLMs

arXiv 预印本 · 技术报告 发表时间 2025.01 Kimi Team · Moonshot AI 多模态 · 文本+视觉 arXiv:2501.12599

一句话：预训练「靠喂数据」的 scaling 总会撞到高质量数据的天花板。Kimi k1.5 提出走另一条扩展轴——用强化学习让模型自己「探索 + 拿奖励」。它的秘诀不是更复杂的算法，而是把上下文窗口扩到 128k，让模型在一条长长的思维链里自己完成「规划、反思、纠错」，从而不用 MCTS、不用价值函数、不用过程奖励模型，就追平了 OpenAI o1。

本页基于 arXiv HTML 版正文（2501.12599v4）与原论文图表构建。术语首次出现时给出英文原词，便于对照原文。文中所有 pipeline 图、结果图均直接取自原论文。

00 TL;DR · 30 秒抓住核心

  • 核心主张：强化学习（RL）是 LLM 继续变强的新 scaling 轴——模型通过「探索 + 奖励」学习，不再被静态数据集卡死。而上下文长度（context length）才是这条轴上最关键的维度。
  • 关键洞见：把上下文扩到 128k 后，模型在一条 long-CoT 里就能完成「规划 / 反思 / 纠错」，相当于把显式搜索树「拍平」成自回归生成的隐式搜索。于是 MCTS、价值函数、过程奖励模型这些复杂组件全都不需要了。
  • 怎么训得动：靠 partial rollouts（部分回滚）把超长轨迹切段复用，加上改进的策略优化（online mirror descent 变体、去掉 value network、保留 negative gradient）、长度惩罚和课程采样。
  • 结果：long-CoT 版在 AIME 77.5、MATH 500 96.2、Codeforces 94 百分位、MathVista 74.9，追平 o1；再用 long2short 把长思维能力压进短模型，short-CoT 版 AIME 60.8，比 GPT-4o / Claude 3.5 高出最多 +550%。
「Scaling 强化学习，为人工智能的持续进步解锁了一条新轴——大模型可以通过学会带着奖励去探索，来扩展自己的训练数据。」

01 问题：预训练撞墙，下一条扩展轴在哪

「next-token 预测 + scaling law」这几年让大模型一路变强：模型参数和数据量按比例放大，智能就持续提升。但这条路有个绕不过去的天花板——

  • 受限于高质量数据总量：预训练能吃的，是已经存在的静态数据集。当高质量语料被用尽，单纯堆数据/参数的收益就会递减。
  • 测试时扩展是个开放难题：OpenAI 的 o1 靠「推理时拉长思维链」（inference-time scaling）取得突破，但方法不公开；此前公开发表的工作都没能复现出有竞争力的结果。
本文要回答的问题
能不能用 RL + LLM 开出一条全新的扩展轴：让模型带着奖励去探索、自己生成训练数据，从而突破静态数据集的限制？如果能，又该用多简单的框架把它跑通、跑到 o1 的水平？

02 旧路线卡在哪：那些被本文「刻意避开」的复杂技术

要让模型学会复杂推理，一个自然的想法是借鉴 AlphaGo：构建一棵思维的搜索树，用价值模型指导，在解空间里系统搜索。学界沿这个方向发展出几套复杂技术。Kimi k1.5 的态度很鲜明：这些它都不用——下面三张卡片解释它们各自的思路与瓶颈，理解了它们，才懂本文「做减法」的价值。

🌳蒙特卡洛树搜索 MCTS 本文避开
把解答拆成思维节点，用价值估计指导，在树上反复展开 / 回溯，搜索最优解题路径。
展开说明 ▸

做法：构造思维搜索树 T，每个节点是「问题 + 一段思维前缀」；用 critic 模型 v 给节点打分，挑最有希望的节点继续展开，直到推出完整解。

卡在哪：推理时需要复杂的并行化（parallelization）来维护和搜索这棵树；token 级的搜索空间巨大，部署代价高。

与本文关系：本文把「搜索树里的全部信息」拍平进一条长上下文，让模型用自回归生成隐式地完成搜索——于是 MCTS 不再需要。

📈价值函数 / 价值网络 本文避开
训练一个和策略同规模的 value network，为每一步推理做「信用分配」（credit assignment）。
展开说明 ▸

做法：像经典 RL（如 PPO）那样，用价值网络估计「当前局面有多好」，据此判断每一步是该加强还是削弱。

卡在哪：① 价值网络额外吃一倍算力；② 更关键——经典信用分配会惩罚「暂时走错但最终纠正」的步骤，而这恰恰是 long-CoT「试错—回溯」最该鼓励的探索行为。

与本文关系：本文直接去掉 value network，只用最终答案对错当奖励信号，鼓励模型大胆探索多样的推理路径。

🧮过程奖励模型 PRM 本文避开
给推理的每一中间步单独打分，提供更细粒度的训练信号。
展开说明 ▸

做法：训练 Process Reward Model 逐步评估推理质量，引导模型走「每步都对」的路径。

卡在哪：通用推理里很难定义、也很难判定「一步」的对错；引入模型化的细粒度奖励，又容易招来奖励作弊（reward hacking）。

与本文关系：本文只用结果级奖励（答案对错 / 编译测试），把简单框架做到极致，反而更稳、更省。

🧩本文的总思路 做减法
不堆复杂组件，而是把「长上下文 + 改进的策略优化」两件事做扎实，让能力自然涌现。
展开说明 ▸

核心赌注：上下文越长 ≈ 可用的「搜索步数」越多。只要能高效地把 RL 训练扩到 128k 上下文，规划 / 反思 / 纠错这些能力就会在 long-CoT 中自发涌现。

两根支柱：① 长上下文扩展（靠 partial rollouts 训得动）；② 改进的策略优化（mirror descent + 采样策略 + 长度惩罚）。

结论：简单框架也能拿到 SOTA，这本身就是论文最想证明的事。

Kimi k1.5 的完整训练分成几个阶段，本报告聚焦在最后的 RL 部分。可以把整条产线理解为「先把底子和模板打好，再用 RL 让推理能力真正长起来」。点「下一步」跟着 checkpoint 一阶段一阶段走：

用 约 100 万条文本 + 100 万条图文样本做通用 SFT：非推理任务靠人工标注 + 排序精修，推理任务（数学 / 代码）靠拒绝采样自动扩样。先在 32k 长度训 1 个 epoch，再到 128k 训 1 个 epoch。

这套方法刻意保持简单，但有四个关键配料（key ingredients）撑起整篇论文，后面会逐一展开：

① 长上下文扩展 核心维度
把 RL 的上下文扩到 128k，并发现性能随上下文变长持续提升。关键工程：partial rollouts——复用上一轮的大段轨迹，避免每次从头重生成。
② 改进的策略优化 算法
为 long-CoT RL 推导出一套公式，采用 online mirror descent 的变体做稳健优化，再配合采样策略、长度惩罚、数据配方。
③ 简洁框架 做减法
长上下文 + 改进优化合在一起，不需要 MCTS / 价值函数 / 过程奖励模型。上下文变长 ≈ 搜索步数变多，规划与反思自然涌现。
④ 多模态 文本 + 视觉
文本与视觉数据联合训练，模型能跨两种模态联合推理（如看图做数学题）。

04 核心洞见：把「搜索树」拍平成一条思维链

这是理解全文的钥匙。经典做法把推理看成在一棵思维搜索树上反复展开与回溯，需要价值模型指导、需要复杂的并行搜索。本文换了个视角：既然搜索树里的所有信息——走过的节点、每步的反馈——本质都是语言 token，那为什么不把它们全部「拍平」进一条长长的上下文，让模型用自回归生成隐式地跑完这场搜索？

显式搜索（旧）：构树 + 规划算法
  • 显式维护一棵思维树 T，节点 = 问题 + 思维前缀
  • 用 critic 模型 v 给每个节点打分
  • 规划算法挑「最有希望」的节点展开 / 遇到死路就回溯
  • 部署时需要复杂并行化来跑这棵树
隐式搜索（本文）：长 CoT 自回归
  • 把整棵树的信息拍平进一条上下文喂给模型
  • 思维 z₁,z₂,… 与「反馈」都当成普通 token 顺序生成
  • 模型在生成中自带规划 / 反思 / 纠错，相当于把搜索内化
  • 推理时只是普通自回归——无需任何并行搜索
为什么「上下文长度」就是这条轴的核心维度
在这个视角下，思维 token 的数量 ≈ 传统规划算法分配的计算预算（搜索步数）。上下文窗口越长，模型能容纳的「搜索步数」就越多，越能探索、回溯、refine。所以扩展上下文 = 扩展模型的「思考深度」——这就是 Kimi k1.5 把 RL 上下文一路推到 128k 的根本动机。

这也解释了 long-CoT 预热（Stage 3）的意义：它先把规划、评估、反思、探索四种认知习惯写进模型，RL 再让这些习惯随着上下文变长而自由生长。最终模型不只是「会按步骤推理」，而是真正学会了发现错误、回溯、改进解法——把已探索过的全部思路都当成上下文来利用。

05 引擎：策略怎么更新（没有 critic 的稳健优化）

有了「长 CoT = 隐式搜索」的视角，接下来的问题是：怎么把 RL 信号高效地灌进模型。本文用 online mirror descent（在线镜像下降）的一个变体，迭代地优化一个带相对熵正则的目标——每一轮都把当前模型当作参考策略 π_θᵢ：

maxθ   E(x,y*)~D [  E(y,z)~πθ[ r(x,y,y*) ]  −  τ·KL( πθ(x) ‖ πθᵢ(x) )  ]
在「拿高奖励」和「别离参考策略太远」之间权衡，τ 控制正则强度。它有闭式解，进而导出可用离线（off-policy）样本优化的代理损失。

对损失求梯度后，最终的更新形式对熟悉策略梯度的人很亲切——它用「同一题 k 个采样的平均奖励」当 baseline，再加一个 l₂ 正则项：

(1/k) Σj [  ∇θ log πθ(yj,zj|x) · ( r(x,yj,y*) − r̄ )  −  (τ/2) ∇θ( log [πθ/πθᵢ] )²  ]
r̄ = 这一题 k 个采样奖励的均值，充当基线（baseline）。这等价于「不要 critic」——用一组答案互比来估计基线，省掉与策略同规模的价值网络。

为什么坚持「不要价值网络」

去掉 value network 不只是省算力。论文给了一个更深的理由，用一个小例子说清：

一个关于「探索」的例子
模型已经写了一段思维 (z₁,…,z_t)，下一步有两个候选：z_{t+1} 直达正解，z'_{t+1} 含有错误。按经典价值函数的信用分配，z'_{t+1} 优势为负、应当被惩罚。但对训练 long-CoT 而言，探索 z'_{t+1} 其实极有价值——只要模型最终能从错误里恢复并到达正解，它就学到了「试错—回溯」的模式。所以本文只用最终答案对错当奖励，鼓励模型大胆探索多样路径，而不是步步求稳。

长度惩罚：治「想太多」（overthinking）

RL 训着训着会出现一个现象：回复越来越长。长一点确实更准，但过度冗长既费算力、人类也不爱看。于是本文加了个长度奖励（length reward）：对同一题采样的 k 个回复，按长度给「相对分数」——

λ = 0.5 − ( len(i) − min_len ) / ( max_len − min_len )

len_reward(i) = λ  （若答对 r=1）   |   min(0, λ)  （若答错 r=0）
同组里越短的正确答案得分越高（鼓励简洁）；错误答案若又长则额外受罚。为避免训练初期被拖慢，长度惩罚先关掉、warmup 之后再常量开启。

采样策略：把算力花在刀刃上

课程采样 Curriculum Sampling
  • 从简单题起步，逐步过渡到难题
  • 初期模型弱，硬刚难题几乎采不到正确样本，效率低
  • 数据自带年级 / 难度标签，天然支持按难度排课
优先采样 Prioritized Sampling
  • 跟踪每道题的成功率 sᵢ
  • 按 1 − sᵢ 的比例采样：越不会做的题被抽得越多
  • 把训练火力集中到模型最弱的地方，学得更快
▸训练配方里的几个工程细节点开看 prompt 筛选 / 代码测试用例 / 数学奖励模型
  • RL prompt 集三原则：覆盖广（STEM/代码/通用推理）、难度均衡、可被准确验证。用 SFT 模型对每题采样 10 次、用通过率当难度代理；并剔除选择题/判断题/证明题等易蒙对的题型。
  • 防奖励作弊：让模型不写 CoT 直接猜答案，若 N=8 次内猜中就判为「太容易被钻空子」并移除。
  • 代码题自动造测试用例：用 CYaRon 库 + 基座模型生成；从 1000 道在线赛题中筛出 614 道无需特判，造出 463 个生成器，最终 323 道入选训练集（用「10 份提交里至少 9 份通过」来验证用例质量）。
  • 数学奖励模型：同一答案可有不同写法（如 a²−4 与 (a+2)(a−2)）。对比两种 RM——经典 value-head RM 抽检准确率 84.4%，而带 CoT 推理再判对错的 Chain-of-Thought RM 高达 98.5%，故 RL 中采用后者。
  • 视觉 RL 数据：真实世界数据 + 合成视觉推理数据 + 文本渲染数据（把文字/代码渲染成图，保证跨模态一致）。

06 基础设施：让 128k 长上下文 RL「训得动」

算法再漂亮，训不动也白搭。长 CoT RL 最棘手的是：轨迹超长且长短不一，一条几万 token 的回复会把系统资源全占住。Kimi k1.5 用一套同步迭代的训练系统 + partial rollouts 来解决。先看整体架构：

图 3(a)（原论文 Figure 3a）：RL 训练系统总览。每一轮迭代由「rollout 阶段（生成轨迹）」和「training 阶段（更新权重）」组成，由中央 Master 协调。
展开说明 ▸
  • Rollout Workers（左上）：负责生成轨迹——拿当前模型对各种输入采样出一串串回复（rollout trajectories）。
  • Trainer Workers（右上）：内含 Policy Model（策略模型） 与 Reference Model（参考模型，即上一轮的 π_θᵢ）；右侧的「gradient update」自环表示它在这里做梯度更新、刷新权重。
  • weight 箭头（实线，Trainer → Rollout）：训练好的最新权重下发给 rollout workers，让下一轮用新策略采样。
  • Master（中央）：总指挥，调度 rollout workers、trainer workers、奖励模型与 replay buffer 之间的数据与通信，做负载均衡。
  • Replay Buffer（右下）：存放轨迹经验，打乱时间相关性，为训练提供多样、无偏的数据；也是 partial rollout 续跑的中转站。
  • Reward Models（左下：Code / Math / K-12 / Vision）：Master 发出「eval request」，由各领域奖励模型评估回复质量；其中代码题还接了代码执行服务（sandbox）做真实判题。
  • 一句话总结：rollout 产数据 → Master 调度 + 奖励打分 → trainer 更新权重 → 新权重回流 rollout，如此同步循环，模型持续自我提升。

  • Hybrid Deployment（混合部署）：训练用 Megatron、推理用 vLLM，通过一个叫 checkpoint-engine 的 shim 进程协调，用 Kubernetes Sidecar 容器共享同一批 GPU，避免训练/推理分开部署时彼此空等。
  • 秒级切换：训练完 Megatron 卸载显存、通过 Mooncake（RDMA）把最新权重传给 vLLM 做 rollout；实测训练→推理 < 1 分钟，反向约 10 秒。
  • 代码沙箱（Code Sandbox）：为代码题提供安全、可复现的执行环境（支持 MultiPL-E、DMOJ、Lean、Jupyter 等）；用 crun 替代 Docker、预建 cgroup、tmpfs overlay 等手段大幅缩短容器启动时间，提高 RL 判题吞吐。

07 long2short：把「长思维」压进短模型

long-CoT 模型很强，但每次都要烧掉很多测试时 token。一个自然的问题是：能不能把它「想得久」积累的思维先验迁移给短模型，让短模型在有限 token 预算下也能打？本文给了四种 long2short 方法，由简到繁：

🔀模型合并 Model Merging
把长 CoT 模型和短 CoT 模型的权重直接平均，无需训练就得到新模型。
展开说明 ▸

做法：最简单的一招——直接对两个模型的权重做平均，融合出一个新模型。

效果：在保持泛化能力的同时提升 token 效率，零训练成本。

✂️最短拒绝采样 Shortest RS
同一题采样 n 次（n=8），只挑最短的正确答案拿去做 SFT。
展开说明 ▸

动机：同一题模型给出的回复长度波动很大，那就挑里头最简洁的正确解。

做法：采样 8 个回复，选出最短且正确的那个作为监督微调样本，引导模型学会简洁作答。

⚖️DPO 偏好优化
把「最短的正确解」当正样本，过长的（含正确但超长）当负样本，构造偏好对训练。
展开说明 ▸

做法：用长 CoT 模型采多个样本，最短正确解 = 正样本；负样本包括「错误的长回复」和「正确但超过正样本 1.5 倍长」的回复。

用途：这些正负偏好对喂给 DPO 训练，直接教模型「同样对，要选短的」。

🏆long2short RL 最优
单独再开一轮 RL，专门收紧长度惩罚和最大回滚长度。
展开说明 ▸

做法：先选一个性能/效率平衡最好的模型当基座，再做一个独立的 long2short RL 阶段：施加（2.3.3 的）长度惩罚，并大幅调小最大 rollout 长度，进一步惩罚那些「虽然可能对但太长」的回复。

效果：实验里它的 token 效率最高——k1.5-short w/ rl 在 AIME 拿到 60.8，平均只用约 3,272 token。

08 有意思的点

除了主线，有几处设计取舍与发现值得单独拎出来——它们往往比 benchmark 数字更能帮你判断这套方法适不适合自己的场景。

📏上下文长度 ＞ 单纯堆参数
小模型靠更长的 CoT，能追平大模型的性能（消融实验 Figure 8）。
展开说明 ▸

同样数据训大小两个模型：大模型起步更高，但小模型靠 RL 优化出的更长 CoT 能追上来。不过大模型token 效率更优。

启发：若追求极限性能，扩大模型 + 扩上下文上限更高、更省 token；若测试算力有预算，训小模型 + 给长上下文是可行解。

➖负梯度很关键（vs ReST）
只「拟合最优答案」不够，必须保留「惩罚错误答案」的负梯度。
展开说明 ▸

ReST 这类方法只反复拟合当前模型采到的最佳答案，不施加负梯度去惩罚错误。消融（Figure 10）显示本文方法样本效率明显更高。

言下之意：在「生成长 CoT」这件事上，负梯度的作用比在其他领域更突出，选对优化算法至关重要。

🧠CoT 奖励模型完胜经典 RM
让奖励模型「先推理再判分」，准确率从 84.4% 跳到 98.5%。
展开说明 ▸

数学答案常有等价的不同写法，判对错并不简单。经典 value-head RM 抽检准确率约 84.4%；让 RM 先生成一段 CoT 推理、再以 JSON 给出判定，准确率升到 98.5%。

启发：奖励模型自己也能从「想一想再下结论」中获益——更可靠的奖励 = 更稳的 RL。

🪶简洁框架本身就是结论
不用 MCTS / 价值函数 / PRM，照样拿 SOTA——这就是论文最想证明的事。
展开说明 ▸

长上下文扩展 + 改进的策略优化，两件事做扎实，就能让规划/反思/纠错自发涌现。复杂技术不是必需品。

价值：给社区一条可复现、可扩展的简洁路线，把注意力从「设计复杂搜索」转回「把 RL 与长上下文做对」。

10 结论与未来方向

论文把自己的核心收获总结得很克制：

  • 上下文长度的扩展，是 LLM 持续变强的关键。配合 partial rollouts 等基础设施优化，长上下文 RL 才训得动、训得起。
  • 改进的策略优化是另一根支柱：把 long-CoT RL 公式化，导出 online mirror descent 变体，再叠加采样策略、长度惩罚、数据配方。
  • 简洁能赢：不靠 MCTS / 价值函数 / 过程奖励模型，照样拿到强性能。
  • long2short 潜力很大：能显著提升短 CoT 模型；未来可把 long2short 与 long-CoT RL 迭代结合，在给定 token 预算下榨出最佳性能。
这篇报告最值得记住的一句话
与其设计越来越复杂的搜索算法，不如把上下文做长、把策略优化做对，让规划与反思在长思维链里自然涌现——再用 long2short 把这份能力压缩到能负担的 token 预算里。未来仍待解决的是：如何进一步提升长上下文 RL 的效率，以及在不损伤探索能力的前提下改进信用分配、减少 overthinking。
