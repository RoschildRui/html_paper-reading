Qwen3 技术报告：一个模型同时学会「深思」与「秒答」

Qwen3 Technical Report · 阿里巴巴 Qwen 团队

arXiv preprint 2025.05 arXiv:2505.09388 Qwen Team Apache 2.0 全部开源

一句话：过去你得在「聊天模型」（快、便宜）和「推理模型」（慢、强）之间来回切换；Qwen3 把思考（thinking）与非思考（non-thinking）两种模式融进同一个模型，还给了一个「思考预算」旋钮让你按需分配算力。模型覆盖 0.6B～235B 的稠密与 MoE 全家桶，预训练 36 万亿 token、支持 119 种语言，小模型靠强到弱蒸馏用约 1/10 的算力就练成。

本页面基于 arXiv HTML 版（v1, 2025-05-14）正文与原始 Figure 1，并补全了 PDF 中的后训练章节（4.4 General RL / 4.5 蒸馏）。术语首次出现时附英文原词，便于对照原文。

00 TL;DR · 30 秒抓住核心

  • 统一思考控制（Thinking Control）：同一个模型既能开启长链推理「想清楚再答」，也能关掉思考「直接快答」，由 /think 与 /no_think 标记切换——再也不用从 Qwen2.5 切到 QwQ 这种「换模型」的笨办法。
  • 思考预算（Thinking Budget）：用户能给思考过程设一个 token 上限，到点就停下来基于已有推理作答，从而在延迟与效果之间自由权衡。增加预算，效果稳定上升。
  • 全家桶：6 个稠密 + 2 个 MoE，参数从 0.6B 到 235B；旗舰 Qwen3-235B-A22B 是 MoE，总参 235B、每 token 仅激活 22B。
  • 大数据 + 多语言：预训练 36 万亿 token，支持语言从 Qwen2.5 的 29 种扩到 119 种。
  • 强到弱蒸馏（Strong-to-Weak Distillation）：小模型不必跑完整四阶段后训练，直接从旗舰模型蒸馏，效果更好、且只需约 1/10 的 GPU 小时。
「把『复杂多步推理』的思考模式与『快速上下文应答』的非思考模式，整合进一个统一框架。」
—— 释义自摘要 “the integration of thinking mode … and non-thinking mode … into a unified framework”

01 问题：为什么需要「两种脑子合一」

2024 年以来，业界事实上分裂出了两类模型：一类是聊天优化模型（如 GPT-4o），响应快、成本低，适合日常对话；另一类是专门的推理模型（如 QwQ、DeepSeek-R1、o1），会先写一长串思维链（chain-of-thought）再作答，数学、代码很强但慢且贵。麻烦在于：

  • 用户被迫「换模型」：简单问题用推理模型是浪费，难题用聊天模型又答不好。要兼顾，就得在两个模型之间来回切，部署、调用都繁琐。
  • 算力无法按需分配：推理模型「想多久」是写死的，用户没法说「这题简单，少想点」或「这题难，多想会儿」。
  • 小模型的后训练太贵：要让每个尺寸的小模型都获得强推理能力，逐个跑完整的 RL/SFT 流水线，算力开销巨大。
本文要回答的问题
能不能让同一个模型同时具备「深思」和「秒答」两种能力，由用户/模板动态切换，还能精确控制思考深度？同时，能否用更省的方式把这套能力传给各个尺寸的小模型？

02 模型家族与架构：稠密 + MoE 全覆盖

架构延续 Qwen2.5 的成熟设计，再做了两处稳定性改动：

  • 沿用：分组查询注意力（GQA）、SwiGLU、旋转位置编码（RoPE）、带预归一化的 RMSNorm。
  • 去掉 QKV-bias：移除 Qwen2 中用过的 QKV 偏置项。
  • 加入 QK-Norm：在注意力里对 Query/Key 做归一化，保证训练更稳。
  • MoE 设计：采用细粒度专家切分（fine-grained expert segmentation），不设共享专家，并用全局批次负载均衡损失（global-batch load balancing loss）鼓励专家分工。

03 核心创新：一个模型，两种模式 + 一个旋钮

这是 Qwen3 最值得理解的设计。模型内部学会了两种作答方式，由输入里的标记决定走哪条路；而「思考预算」则让你连思考的深度都能调。

🧠 思考模式 /think
先在 <think>…</think> 块里写出长链推理（long-CoT），再给最终答案。适合数学、代码、逻辑等复杂多步任务。默认即为此模式。
⚡ 非思考模式 /no_think
跳过推理，直接基于上下文快速作答；回复里仍保留一个空的 think 块以维持格式一致。适合闲聊、简单问答等低延迟场景。

怎么切换：靠聊天模板里的标记

用户只需在 query 或 system message 里写上 /think 或 /no_think，模型就按最后一个标记决定是否思考。多轮对话里可以反复切换，模型遵循「最近一次」的标记。

💬 聊天模板示意（释义自原文 4.3 节）
# 非思考模式：用户加 /no_think，模型回复里 think 块为空
<|im_start|>user
广州的省会是哪里？ /no_think<|im_end|>
<|im_start|>assistant
<think>

</think>

广东省的省会是广州。<|im_end|>

# 思考模式：/think 可省略（默认），模型先写推理再作答
<|im_start|>user
求 1 到 100 的和。 /think<|im_end|>
<|im_start|>assistant
<think>
等差数列求和：(1+100)×100/2 = 5050 …
</think>

答案是 5050。<|im_end|>

在 Hugging Face 的 tokenizer 里，这一行为通过参数 enable_thinking=False 即可关闭思考。

思考预算：到点就「收手」

当思考模式与非思考模式都被模型掌握后，它会自然涌现出一种中间能力：在思考没写完的情况下也能给出回答。基于这点，框架可以做预算控制——当思考长度达到用户设定的阈值时，手动截断并插入一句停止指令，模型随即基于已有推理给出最终答案。

截断时插入的停止指令（原文原话）
「Considering the limited time by the user, I have to give the solution based on the thinking directly now.</think>」
值得注意：这种「想到一半也能作答」的能力并非显式训练得到，而是 Thinking Mode Fusion 之后自然产生的。增大思考预算，模型在各类任务上的表现会持续提升。

04 预训练：36T token、119 种语言、三阶段

相比 Qwen2.5，Qwen3 把预训练 token 翻了一倍、语言数翻了三倍：在 119 种语言和方言上、用 36 万亿 token 训练。数据怎么来、怎么配比，是这一节的重点。

数据从哪来

  • PDF 文本抽取：先用 Qwen2.5-VL 对海量 PDF 文档做文字识别，再用 Qwen2.5 精修文本质量，由此多得到数万亿高质量 token。
  • 合成数据：用 Qwen2.5、Qwen2.5-Math、Qwen2.5-Coder 合成教材、问答、指令、代码片段等数万亿 token，覆盖数十个领域。
  • 实例级数据配比：不同于以往在「数据源 / 领域」层面调配比的做法，Qwen3 给 30T+ token 打上教育价值、领域、安全等细粒度标签，在单条样本（instance-level）粒度上优化数据混合比例。

三阶段训练

从打地基，到强化推理，再到拉长上下文，逐级推进：

STAGE S1通用阶段（General Stage）
在 30T+ token 上以 4,096 序列长度训练，打牢语言能力与世界知识，覆盖全部 119 种语言。
↓
STAGE S2推理阶段（Reasoning Stage）
提高 STEM、代码、推理、合成 数据占比，再用约 5T 更高质量 token（序列长仍为 4,096）训练，并加快学习率衰减，强化推理能力。
↓
STAGE S3长上下文阶段（Long Context Stage）
在数千亿 token 上把序列长度提到 32,768（其中 75% 长度在 16K–32K）。RoPE 基频用 ABF 技术从 1万提到 100万，并引入 YARN + Dual Chunk Attention（DCA），推理时上下文可再扩 4 倍。

团队还为三个阶段分别建立了缩放律（scaling laws），用小代理模型预测每个稠密 / MoE 模型的最优学习率与 batch size。

05 后训练：四阶段流水线（重头戏）

预训练给出的是「会说话」的基座模型；要让它既会深思、又会快答、还听话，靠的是后训练。整套流程围绕两个目标设计：思考控制（前文已讲）和强到弱蒸馏。下面这张原文 Figure 1 是理解全文的关键——先看图，再跟着分步动画走一遍。

图 1 · Qwen3 后训练流程（Post-training pipeline）。旗舰模型（Qwen3-235B-A22B、Qwen3-32B）从基座出发，依次经过四个阶段；轻量模型（Qwen3-30B-A3B 及 14B/8B/4B/1.7B/0.6B）则改走右下角的「强到弱蒸馏」分支。
展开图解说明 ▸
  • 左侧入口 · 基座模型（Base Models）：流程的起点是预训练得到的 Base 模型，本身只会续写、不会按指令对话，也没有可控的思考行为。
  • 上方主链 · 四阶段（针对旗舰模型）：图中蓝色主轴自左向右是 Stage 1 长链冷启动 → Stage 2 推理 RL → Stage 3 思考模式融合 → Stage 4 通用 RL。前两阶段专攻「思考」能力，后两阶段把「非思考」能力融合进来并做全面对齐。箭头代表上一阶段的模型权重作为下一阶段的初始化，逐级强化。
  • 阶段一 Long-CoT Cold Start：用精筛的长思维链数据做 SFT，给模型「种」下基础推理模式，但刻意不追求即时分数，给后续 RL 留足提升空间。
  • 阶段二 Reasoning RL：用 GRPO 在 3,995 条高难度「问题-验证器」上做强化学习，让推理能力大幅跃升。
  • 阶段三 Thinking Mode Fusion：继续 SFT，把「非思考」数据与「思考」数据混合训练，让同一个模型掌握两种模式与思考预算控制。
  • 阶段四 General RL：在 20+ 类任务上做通用 RL，全面提升指令遵循、格式遵循、偏好对齐、Agent 工具调用等能力。
  • 右下分支 · 强到弱蒸馏（Strong-to-Weak Distillation）：轻量模型不重复跑这条昂贵的四阶段链，而是直接从已练好的旗舰/大模型蒸馏知识，省下约 9/10 的算力。这条分支是图中独立于主链的另一条数据流。

总结：上方主链负责「把旗舰模型练到极致」，右下分支负责「把这份能力低成本复制给小模型」——两条路共同支撑起 Qwen3 整个家族。

为什么是「先思考、后融合」的顺序
前两阶段在「干净」的推理目标下把思考能力顶到尽可能高；后两阶段再把非思考能力与人类偏好融进来。若顺序反过来，强行先对齐通用能力，往往会压低推理上限——这也是为什么「思考」要先练、「非思考」靠 SFT 融合而非从头混训。

06 强到弱蒸馏：小模型的「捷径」

给每个尺寸的小模型都跑一遍上面那条四阶段流水线，太贵了。Qwen3 的做法是：让大模型当老师，把能力直接蒸馏给 5 个稠密小模型（0.6B / 1.7B / 4B / 8B / 14B）和 1 个 MoE 小模型（30B-A3B）。蒸馏分两步：

PHASE 1 · OFF-POLICY
离策略蒸馏
把教师模型在 /think 与 /no_think 两种模式下生成的输出合在一起，让学生模型先学会基础推理、并掌握模式切换，为下一步打基础。
学生先「看老师答」
PHASE 2 · ON-POLICY
在策略蒸馏
学生模型自己生成（/think 或 /no_think）回答，再把它的 logits 与教师（Qwen3-32B 或 235B-A22B）对齐，最小化 KL 散度来微调。

这条结论很关键：蒸馏不仅更省，效果还同时优于「在小模型上直接做 RL」——既提升了即时正确率（Pass@1），也提升了探索多样性（Pass@64）。这意味着小模型不必各自苦练，继承大模型的能力是更划算的路线。

07 有意思的点

除了主线，有几处设计取舍与发现值得单独拎出来——它们往往比 benchmark 数字更能帮你判断这套方法适不适合自己的场景。

🎛️思考预算是「涌现」的
「想到一半也能作答」的能力没被显式训练，是模式融合后自然出现的副产品。
展开说明 ▸

一旦模型同时掌握思考与非思考两种模式，它就天然能处理「思考不完整」的中间态。于是只要在思考达到阈值时截断、插一句停止指令，模型就能基于已有推理收尾。

启发：很多产品化能力（如可调推理深度）未必要专门训练，可能藏在更基础的能力组合里。

🔁蒸馏 > 小模型直接 RL
从强模型蒸馏，比让小模型自己 RL 既更强又更省（约 1/10 GPU 小时）。
展开说明 ▸

蒸馏同时拉高了 Pass@1（准确）和 Pass@64（探索），说明学生不是「死记答案」，而是真的继承了推理模式。而直接在小模型上做大规模 RL，算力惊人却未必更好。

言下之意：推理模式的「发现」依赖大模型，小模型更适合当「继承者」。

🧩统一模型，告别「换模型」
把聊天模型和推理模型合一，部署、调用、体验都简化了。
展开说明 ▸

以前要兼顾速度与深度，得同时维护 GPT-4o 式聊天模型和 QwQ 式推理模型，按场景切换。Qwen3 用一个模型 + 一个标记解决，降低了系统复杂度。

边界：两种模式共享一套权重，意味着训练时必须小心融合顺序，避免「学了非思考、忘了思考」。

🏷️实例级数据配比
不在「领域」层面调数据比例，而是细到每一条样本。
展开说明 ▸

团队给 30T+ token 打上教育价值、领域、安全等细粒度标签，再用小代理模型做大量消融，在 instance-level 优化数据混合——比传统按数据源/领域配比更精细。

价值：更精准的数据配比，是 Qwen3 用更少参数追上更大模型的「隐形功臣」之一。

09 结论与展望

Qwen3 把思考 / 非思考双模式 + 思考预算整合进统一模型，预训练 36T token、覆盖 119 种语言，并用强到弱蒸馏低成本武装了整个小模型家族；全部模型以 Apache 2.0 开源。原文给出的未来方向：

  • 继续扩规模：用质量更高、内容更多样的数据扩大预训练。
  • 改进架构与训练：面向高效压缩、超长上下文等目标优化模型结构与方法。
  • 加码 RL 与 Agent：把更多算力投入强化学习，尤其是从环境反馈中学习的 Agent 系统，构建能处理复杂任务、具备推理时扩展能力的智能体。
这篇报告最值得记住的一点
与其维护「聊天模型 + 推理模型」两套系统，不如把两种能力融进一个可控的模型，再用蒸馏把能力廉价复制给小模型——Qwen3 用一套统一框架，把「快」「准」「省」尽量都占齐了。
