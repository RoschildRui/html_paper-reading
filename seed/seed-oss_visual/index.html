Seed-OSS：字节 Seed 开源的
36B 长上下文 / 强推理基础模型

仅用 12T tokens 训练，原生支持 512K 上下文，可由用户手动控制「思考预算」(thinking budget)，并以 Apache-2.0 协议全面开源。面向 agent、工具调用与长文本场景。

官方开源发布 (open-source release) 发布 2025.08（2025/08/20） ByteDance Seed Team Apache-2.0 GitHub ↗ Hugging Face ↗

⚡ TL;DR — 30 秒看懂

它是什么：Seed-OSS 是字节跳动 Seed 团队开源的一系列36B 稠密大语言基础模型（含 Base、Base-woSyn、Instruct 三个变体），原生支持 512K 超长上下文，仅用 12T tokens 预训练就在多个公开基准上取得开源 SOTA 级表现。

最大亮点：「思考预算」可手动控制——用户能指定模型最多思考多少 token，模型在推理过程中还会周期性地自我汇报已用 / 剩余预算，预算用尽即给出最终答案，从而在精度与推理成本之间灵活权衡。

为什么重要：采用 Apache-2.0 商用友好协议；同时开源「含 / 不含合成指令数据」两个 Base 版本，方便后训练研究；在推理、数学、代码、agent 工具调用与长上下文上都有强表现。

01 为什么做这个开源模型

开源社区不缺模型，缺的是「既能强推理、又能跑长文本、还对开发者足够友好」的基础模型。Seed-OSS 想一次性把这几件事补齐。

过去一年开源基础模型层出不穷，但开发者在真正落地时常被几个现实问题卡住：推理任务想要更长更深的思维链，却没法控制「到底让模型想多久」；长文档场景需要原生大窗口，而不是靠外推硬撑；做后训练研究时，又因为预训练里混入了合成指令数据，难以判断是「模型本身强」还是「被指令数据带强」。Seed-OSS 把官方的设计目标概括为几条对开发者直接有用的特性：

  • 可控的思考长度：让用户按需调节推理长度，在实际场景里平衡精度与推理效率。
  • 强推理 + 均衡通用能力：专门为推理任务优化，同时不牺牲通用能力。
  • Agentic 智能：在工具调用、issue 解决等 agent 任务上表现突出。
  • 研究友好：同时放出「含 / 不含合成指令数据」两个预训练版本，给社区更干净的对照基线。
  • 原生长上下文：训练阶段就用最高 512K 的长上下文，而非事后外推。
一个定位说明：官方明确 Seed-OSS 主要面向国际化 (i18n) 场景、以英文为主要优化与评测语言；其它语言能力有限、未经充分测试。把它当作一个英文优先的强基础模型来用最稳妥。

02 模型与架构

Seed-OSS 没有走花哨的新架构，而是采用业界成熟、可复现的稠密 causal LM 配方，把工程确定性放在第一位。

整个系列是 36B 参数的稠密（dense）因果语言模型，采用当下主流的组合：RoPE 旋转位置编码、GQA 分组查询注意力、RMSNorm 归一化与 SwiGLU 激活。它不是 MoE，所有参数对每个 token 都参与计算；卖点不在「稀疏省算力」，而在长上下文 + 可控推理 + 数据干净。

03 招牌能力：思考预算 (Thinking Budget)

这是 Seed-OSS 最有辨识度的特性：你可以像设「字数上限」一样，告诉模型「这次最多思考 N 个 token」，模型会一边推理一边盯着自己的预算条。

大多数推理模型只能在「想很久」与「直接答」之间二选一。Seed-OSS 把思考长度变成一个可调旋钮：在调用时通过 thinking_budget 指定预算，模型就会在 <seed:think> 内部推理，并周期性插入 <seed:cot_budget_reflect> 标签来自我汇报已消耗与剩余的 token；当预算耗尽（或推理自然结束）时，立刻收束并给出最终答案。

  • 默认模式：不设预算（thinking_budget = -1）时，模型不限长度地思考。
  • 推荐取值：优先用 512 的整数倍（512、1K、2K、4K、8K、16K），因为模型在这些区间被充分训练过。
  • 直接作答：预算设为 0 时模型不思考直接回答；官方建议把任何低于 512 的预算都当作 0 处理。

▶ 在 Transformers 里设置思考预算 · apply_chat_template 传入 thinking_budget（点开看代码） 
# pip install transformers>=4.56.1
from transformers import AutoModelForCausalLM, AutoTokenizer

model_name = "ByteDance-Seed/Seed-OSS-36B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, device_map="auto")

messages = [{"role": "user", "content": "How to make pasta?"}]
tokenized_chat = tokenizer.apply_chat_template(
    messages, tokenize=True, add_generation_prompt=True,
    return_tensors="pt",
    thinking_budget=512   # 控制思考预算（-1 表示不限）
)
outputs = model.generate(tokenized_chat.to(model.device), max_new_tokens=2048)
print(tokenizer.decode(outputs[0]))

04 其他关键亮点

除了思考预算，Seed-OSS 还有三个对开发者和研究者都很实在的设计。点开每张卡片看它解决什么问题。

▶
原生 512K 长上下文 长文本
训练阶段就用最高 512K 长上下文，而非事后外推

Seed-OSS 在预训练时原生（natively）就采用最高 512K（524,288）token 的上下文窗口，配合 RoPE 基频 1e7。这意味着长文档问答、长代码库、长对话历史等场景不必依赖事后外推（extrapolation）来硬撑窗口。

在长上下文基准 RULER (128K) 上，Seed-OSS-36B-Instruct 取得 94.6，是对比开源模型中的最高分，印证了长窗口不只是「能塞进去」，而是「真能用」。

▶
Agentic 智能：工具调用与 issue 解决 Agent
在 tool-use 与软件工程类 agent 任务上表现突出

官方把 agent 能力列为核心卖点之一。在工具调用基准 TAU1-Retail 上达到 70.4（对比开源最佳），在软件工程基准 SWE-Bench Verified (OpenHands) 上达到 56、Multi-SWE-Bench 达到 17。

部署上也对 agent 友好：vLLM 推理时提供专门的工具调用解析器 --tool-call-parser seed_oss，可直接接入 OpenAI 风格的 tool call 流程。

▶
研究友好：含 / 不含合成指令数据的双 Base 版本 研究
提供更干净的对照基线，避免合成指令数据干扰后训练研究

在预训练中加入合成指令数据通常能提升大多数基准表现，但也会污染后训练（post-training）研究——很难分清提升来自模型本身还是合成数据。为此官方放出两个 Base：

  • Seed-OSS-36B-Base（w/ syn.）：含合成指令数据，作为默认高性能基座。
  • Seed-OSS-36B-Base-woSyn（w/o syn.）：不含合成指令数据，给研究社区一个「不受合成数据影响」的干净基线。

两者在不同基准上互有高低（例如 woSyn 在 SimpleQA、GPQA-D 上反而更高），正好方便研究者做对照实验。

06 开源细节

Seed-OSS 是「真开源」：权重、推理脚本、采样建议、工具调用解析器都给齐，协议宽松，可直接商用。

  • 协议：Apache-2.0，允许商用与二次开发。
  • 发布时间：2025/08/20 释出 Base、Base-woSyn 与 Instruct。
  • 提供变体：Seed-OSS-36B-Base、Seed-OSS-36B-Base-woSyn、Seed-OSS-36B-Instruct。
  • 权重分发：Hugging Face 上的 ByteDance-Seed 组织 / Seed-OSS 合集。
  • 推理：支持 Transformers（generate.py，含 4/8-bit 量化）与 vLLM（≥0.10.2，含 seed_oss 工具调用解析器）。
  • 技术报告：官方标注「Tech Report Coming Soon」（尚未发布，本页基于 README / MODEL_CARD）。

07 局限与安全

官方在 MODEL_CARD 里对能力边界和安全使用做了明确说明，落地前值得先看一眼。

  • 语言局限：主要面向并评测于英文（i18n），其它语言能力有限、未充分测试。
  • 训练数据局限：以公开数据为主，对特定文化、价值观、历史事件的理解可能不完整；知识截止 2024/07。
  • 幻觉：与所有 LLM 一样，可能生成不正确甚至虚构的内容。
  • 有害内容：尽管做了大量安全训练，仍可能产生有害 / 不准确 / 冒犯性输出，建议开发者自测并加人工监督。

安全方面，官方称从训练数据准备到训练与评测全周期都做了内容安全措施，并在发布前经过由新加坡全球安全团队主导的多轮安全审查：包括训练数据过滤（清除 CSAM / 高毒内容、移除 PII）、安全微调（在 SFT 与 RLHF/PPO 阶段）以及常态化与对抗性安全测试。模型卡也列出了禁止用途（医疗 / 法律 / 金融专业建议、高风险自动决策、未成年人安全相关、违法活动、仇恨骚扰、虚假信息、军事监控等）。

「Although trained with only 12T tokens, Seed-OSS achieves excellent performance on several popular open benchmarks.」——官方 README（仅用 12T tokens 训练，却在多个流行公开基准上取得优异表现。）
