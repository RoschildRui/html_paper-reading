Qwen3 技术报告

把「会思考的推理模型」和「快速回答的对话模型」
合并进同一个、可调档的模型族

2025.05 arXiv preprint · 2505.09388 Qwen Team（阿里巴巴） Apache 2.0 开源 cs.CL

Qwen3 是通义千问家族的最新一代开源大模型，覆盖从 0.6B 到 235B 的 8 个模型（含稠密 Dense 与混合专家 MoE 两种架构）。它最核心的改变是：不再需要在「对话模型」和「推理模型」之间切换——thinking（深度推理）与 non-thinking（快速回答）两种模式被融合进同一个模型，用户用一行标记 /think、/no_think 就能实时切换，还能通过「思考预算」精确控制模型该想多久。配合「强到弱蒸馏」，小模型的训练成本大幅降低；预训练数据扩展到 36 万亿 tokens、覆盖 119 种语言。

01 为什么需要 Qwen3

过去要同时做好「快速对话」和「深度推理」两件事，往往得部署两个不同的模型：一个像 GPT-4o 那样擅长即时、贴合上下文的对话；另一个像 QwQ-32B、o1 那样擅长多步推理。用户和开发者必须在它们之间手动切换——既麻烦，又要承担双份的部署与维护成本。

Qwen3 的回答是：把两种能力装进同一个模型，让模型根据用户输入或聊天模板动态决定「现在要不要思考、思考多深」。这正是后面所有训练设计（尤其是后训练流程）真正服务的目标。

过去两个模型
  • 对话模型（如 GPT-4o 类）负责快速回答
  • 推理模型（如 QwQ-32B / o1 类）负责多步思考
  • 切换任务＝切换模型，流程割裂
  • 同时部署两套，成本翻倍
Qwen3一个模型
  • 单一模型同时具备思考 / 非思考两种模式
  • /think、/no_think 标记实时切换
  • 「思考预算」精细控制推理深度
  • 只需部署一份，省算力、省运维

02 模型家族一览

Qwen3 一次性发布 6 个稠密模型（0.6B / 1.7B / 4B / 8B / 14B / 32B）和 2 个 MoE 模型（30B-A3B、235B-A22B），满足从端侧到旗舰的不同需求。旗舰 Qwen3-235B-A22B 总参数 235B、每 token 仅激活 22B——兼顾性能与推理效率。

03 架构

Dense 模型整体沿用 Qwen2.5 已经被验证成熟的设计：GQA（分组查询注意力）、SwiGLU、RoPE（旋转位置编码）、带 pre-norm 的 RMSNorm。在此之上，Qwen3 做了两处面向训练稳定性的改动；MoE 模型则在专家设计上做了更细的优化。点开下面卡片看每一处改动的来龙去脉。

🧭QK-Norm（替代 QKV-bias）
去掉 Qwen2 的 QKV-bias，给注意力引入 QK-Norm，让训练更稳。
展开 ▸

Qwen2 在注意力中使用 QKV-bias，Qwen3 将其移除，并在注意力机制中引入 QK-Norm。这一改动的目的是确保 Qwen3 的训练稳定性，避免大规模训练中出现的不稳定现象。其余组件（GQA、SwiGLU、RoPE、RMSNorm + pre-norm）与 Qwen2.5 保持一致。

🧩细粒度专家分割
MoE 共 128 个专家，每个 token 激活其中 8 个。
展开 ▸

Qwen3-MoE 沿用 Qwen2.5-MoE 的思路，采用 细粒度专家分割（fine-grained expert segmentation）。两个 MoE 模型都设有 128 个专家，每个 token 路由到 8 个激活专家。更细的专家划分让每个专家更专注，提升参数利用效率。

✂️去掉共享专家
与 Qwen2.5-MoE 不同，Qwen3-MoE 不设共享专家。
展开 ▸

Qwen2.5-MoE 中存在「共享专家」（shared experts，所有 token 都会经过），而 Qwen3-MoE 取消了共享专家。这是 Qwen3 MoE 设计与上一代的一个明确区别，配合下面的负载均衡策略一起鼓励专家分工。

⚖️全局批负载均衡
用 global-batch 负载均衡损失鼓励专家专业化。
展开 ▸

Qwen3 采用 global-batch load balancing loss（全局批负载均衡损失），让不同专家在整个批次范围内被均衡地使用，从而鼓励专家专业化。论文指出，这些架构与训练上的改进共同带来了下游任务上的显著提升。

分词器沿用 Qwen 的 BBPE（byte-level byte-pair encoding），词表大小 151,669。

04 预训练

数据：怎么把语料扩到 36 万亿 tokens

相比 Qwen2.5，Qwen3 的语料规模和多样性都大幅提升：token 数翻倍、语言数翻三倍（29 → 119 种语言和方言），总量约 36 万亿 tokens。扩充语料主要靠三招：

  • PDF 文本提取：先用 Qwen2.5-VL 对海量 PDF 类文档做文字识别，再用 Qwen2.5 精修识别结果，最终额外得到数万亿高质量文本 tokens。
  • 合成数据：用 Qwen2.5、Qwen2.5-Math、Qwen2.5-Coder 合成教材、问答、指令、代码片段等多种格式，覆盖数十个领域，规模同样达数万亿 tokens。
  • 实例级数据配比：自研多语言标注系统，对 30 万亿以上 tokens 按「教育价值 / 领域 / 安全」等维度打标；不同于 DoReMi、DoGE、RegMix 在领域级别调配比，Qwen3 用小代理模型做大量消融，在 instance（实例）级别优化数据混合。

三阶段预训练：打基础 → 强推理 → 拉长上下文

预训练分三个阶段递进，序列长度从 4K 一路扩到 32K：

基座模型评测：更少参数，更强表现

在 15 个基准（涵盖通用、数学/STEM、代码、多语言）上，Qwen3 基座模型的几条关键结论：

Qwen3-235B-A22B-Base 在 15 个基准中的 14 个上超过 DeepSeek-V3-Base，却只用约 1/3 总参数、2/3 激活参数。
Qwen3-32B-Base 在 10/15 个基准上超过上一代旗舰稠密模型 Qwen2.5-72B-Base（如 MMLU-Pro 65.54 vs 58.07），参数还不到一半。
MoE 架构红利：用 1/5 的激活参数即可达到同等稠密模型的水平，大幅降低推理与训练成本。

05 后训练流程（重头戏）

后训练是把「思考 / 非思考」两种能力真正塑造进模型的地方，它有两条并行的主线：

  • 旗舰模型走完整的四阶段流程：前两阶段练「思考」，后两阶段融入「非思考」。
  • 轻量模型不重复跑四阶段，而是直接从旗舰模型做强到弱蒸馏（详见第 07 节「蒸馏」），省下大量算力。
图片暂时无法加载，可点击 这里在原文查看 Figure 1。流程：旗舰模型 Base → Stage 1 Long-CoT Cold Start → Stage 2 Reasoning RL → Stage 3 Thinking Mode Fusion → Stage 4 General RL → Qwen3-235B-A22B / 32B；轻量模型 Base → Strong-to-Weak Distillation → 30B-A3B / 14B / 8B / 4B / 1.7B / 0.6B，由旗舰模型输出喂入蒸馏。
图 1：Qwen3 后训练流程。上半部分是旗舰模型的四阶段训练，下半部分是轻量模型的蒸馏路径。（图源：原论文 Figure 1）
展开说明 ▸
  • 上半（Flagship Models，暖色区）：旗舰模型从 Base 出发，依次经过 Stage 1 → Stage 2 → Stage 3 → Stage 4，最终产出红框中的 Qwen3-235B-A22B 与 Qwen3-32B。
  • Stage 1 · Long-CoT Cold Start：用长链式思维数据冷启动，给模型「种下」推理范式。
  • Stage 2 · Reasoning RL：强化学习专攻数学、代码等可验证推理任务，把推理能力顶上去。
  • Stage 3 · Thinking Mode Fusion：把「非思考」能力融合进已有的「思考」模型，让一个模型兼具两种模式。
  • Stage 4 · General RL：通用领域强化学习，在广泛下游任务上做最后的对齐与打磨。
  • 下半（Lightweight Models，冷色区）：轻量模型 Base 不走四阶段，而是经过 Strong-to-Weak Distillation 得到 30B-A3B / 14B / 8B / 4B / 1.7B / 0.6B。
  • 跨区箭头：从旗舰最终模型有一条箭头向下指向蒸馏框——意味着小模型的「老师」正是训练完成的旗舰模型。

一句话总结：旗舰靠四阶段「炼」出来，小模型靠蒸馏「教」出来，两条线在蒸馏处汇合。

S1
Long-CoT 冷启动 Long-CoT Cold Start
用精挑细选、可验证的长链思维数据给模型「种下」推理范式，但刻意不追求刷分。
▶

动机：在做强化学习之前，先让模型学会「长链式思维（long-CoT）」的基本样子。这一步求的是「种下好的推理范式」，而不是马上把分数刷高。

数据怎么构建：两阶段过滤

数据覆盖数学、代码、逻辑推理、通用 STEM，每道题都配有可验证的参考答案或测试用例。构建经过严格的两轮过滤：

① Query 过滤：用 Qwen2.5-72B-Instruct 剔除不易验证的问题（含多个子问题、或纯文本生成类）；并剔除「不用 CoT 就能答对」的题，防止模型靠浅层猜测；同时标注领域，保持各领域均衡。

② Response 过滤：用 QwQ-32B 为每道题生成 N 个候选答案（QwQ-32B 始终答不对时由人工评估）。对 Pass@N 为正的题，再剔除以下响应：①最终答案错误；②大量重复；③明显是猜测、缺乏推理；④思考过程与总结结论不一致；⑤语言混杂或风格突变；⑥疑似与验证集过于相似。

关键取舍：此阶段刻意少样本、少步数，目的是不限制模型潜力，为后续 RL 留出提升空间。

S2
推理强化学习 Reasoning RL
用 3,995 对高难度可验证题做 GRPO 强化学习，AIME'24 从 70.1 一路涨到 85.1。
▶

数据筛选的四条标准：用于本阶段的「题—验证器」对必须满足：① 没在冷启动阶段用过；② 对冷启动后的模型是「可学的」；③ 尽可能难；④ 覆盖广泛子领域。

最终收集 3,995 对「题—验证器」，采用 GRPO 更新模型参数。训练上的经验：用大 batch + 每题高 rollout 次数，并引入off-policy 训练提升样本效率；同时通过控制模型熵（entropy）稳步上升或保持平稳，来平衡探索与利用，这对稳定训练至关重要。

结果

单次 RL 运行、无需人工干预超参，训练奖励与验证性能持续提升。例如 Qwen3-235B-A22B 的 AIME'24 成绩在 170 个 RL 步内从 70.1 提升到 85.1。

S3
思考模式融合 Thinking Mode Fusion
在推理模型上继续 SFT，把「非思考」能力融进来，并设计聊天模板实现模式切换。
▶

目标：把「非思考」能力融合进 Stage 2 已经练好的「思考」模型，让开发者既能控制推理行为，又不用为两种模式分别部署模型。做法是在 Reasoning RL 模型上做持续 SFT，并设计聊天模板来融合两种模式。

SFT 数据怎么配

思考数据：用 Stage 2 模型自己对 Stage 1 的 query 做拒绝采样生成——这样保证不损害 Stage 2 已有的推理性能。非思考数据：精心覆盖代码、数学、指令遵循、多语言、创意写作、问答、角色扮演等多样任务，并用自动生成的 checklist 评估质量；为提升低资源语言表现，特意提高了翻译任务比例。

本阶段顺带带来两个关键机制：聊天模板（模式切换）与思考预算（深度控制）——它们正是下一节「思考控制」的主角。

S4
通用强化学习 General RL
通用领域 RL，在广泛下游任务上做最后的对齐与性能打磨。
▶

定位：后两个阶段（Stage 3 + Stage 4）共同负责把「非思考」能力整合进模型。Stage 3 先把带推理路径与不带推理路径的数据合并成一个统一数据集做 SFT；Stage 4 在此基础上做通用领域强化学习。

这一步在优化什么

General RL 在广泛的下游任务类型上施加强化学习信号，目标是全面提升模型在各类真实任务上的综合表现与对齐（而不再局限于前两阶段聚焦的数学 / 代码推理），最终产出旗舰模型 Qwen3-235B-A22B 与 Qwen3-32B。

06 思考控制：聊天模板 + 思考预算

这是 Qwen3 最核心的创新落地。模式融合之后，怎么让用户来控制模型「想不想」「想多久」？答案是两套机制：用聊天模板切换模式，用思考预算控制深度。

机制一：聊天模板切换模式

模式切换靠聊天模板里的 /think 与 /no_think 标记——它们既可以写在用户 query 里，也可以写在 system message 里。默认是思考模式：为了让模型在没有任何标记时也会思考，团队特意加入了「用户 query 不含 /think」的思考模式训练样本，因此 /think 通常可省略；而加上 /no_think 就关闭思考。一个关键设计：非思考模式下仍保留一个「空的 think block」——既保证模型内部格式一致，也让开发者可以直接拼一个空 think block 来强制关闭思考。多轮对话里可随机插入多个标记，模型以最后一个标记为准。下面是两种模式的模板对比（对应论文 Table 9）：

🧠 思考模式（默认）
<|im_start|>user
{用户问题} /think<|im_end|>   # /think 是默认，可省略
<|im_start|>assistant
<think>
{模型的多步推理过程……}
</think>

{最终回答}<|im_end|>
⚡ 非思考模式
<|im_start|>user
{用户问题} /no_think<|im_end|>
<|im_start|>assistant
<think>
</think>   # 保留空的 think block

{最终回答}<|im_end|>

在 Hugging Face 的 tokenizer 里，这一行为通过参数 enable_thinking=False 实现。

机制二：思考预算（一步步看它怎么工作）

既然模型能在「完整思考」和「完全不思考」之间自如切换，它自然也学会了处理「思考到一半」的情况——这正是思考预算的基础。值得注意：这个能力不是被显式训练出来的，而是模式融合之后「涌现」的。点「下一步」跟着走一遍：

思考 tokens 累积中…
① 用户提问 + 设定思考预算
用户提出一个复杂问题，同时设定一个「思考预算」上限（例如：思考最多用掉某个 token 数）。此时模型还没开始思考。
② 模型进入思考模式，逐步累积推理
模型在 <think> 块里一步步推理，思考 tokens 不断累积——进度条向右增长。
③ 思考长度逼近预算上限
推理还在继续，长度逐渐接近用户设定的阈值（进度条触及竖线标记）。
④ 达到阈值 → 手动截断 + 注入停止指令
一旦思考长度达到阈值，系统手动中止思考，并向序列中注入一句停止指令（见下方），强制收尾 think 块。
⑤ 基于已有推理，直接作答
收到停止指令后，模型基于到目前为止积累的推理直接生成最终答案——在「想得更久」和「答得更快」之间完成权衡。
注入的停止指令（论文原文）：
Considering the limited time by the user, I have to give the solution based on the thinking directly now.
</think>
✓ 最终答案已基于「不完整但已足够」的推理生成 —— 这一能力是模式融合后自然涌现的。

07 强到弱蒸馏：小模型怎么便宜地造出来

让每个小模型都跑一遍完整四阶段训练太贵了。Qwen3 对 5 个稠密模型（0.6B / 1.7B / 4B / 8B / 14B）和 1 个 MoE 模型（30B-A3B）改用强到弱蒸馏：用已经训练好的旗舰 Qwen3-32B 与 Qwen3-235B-A22B 当「教师」，把能力迁移给小「学生」。注意——目标不只是提性能，还要把 /think / /no_think 的模式切换能力一并传给小模型。整个过程分两个阶段，顺序很关键：

PHASE 1
Off-policy 蒸馏
把教师在 /think 与 /no_think 两种模式下生成的输出合在一起，让学生对这些「教师答案」做响应蒸馏。学生由此先学到基本推理能力与模式切换，为下一阶段打基础。
学生学「教师的输出」
PHASE 2
On-policy 蒸馏
学生自己采样 prompt、在 /think 或 /no_think 模式下生成响应（on-policy 序列）；再对齐学生与教师（32B 或 235B-A22B）的 logits、最小化 KL 散度来微调。
学生学「教师的概率分布」

关键证据：蒸馏 vs 直接强化学习

论文做了一个很干净的对照实验：从同一个「off-policy 蒸馏后的 8B 检查点」出发，分两条路继续训练——要么直接做强化学习（RL），要么做 on-policy 蒸馏（两边都只用数学 + 代码数据）。结论非常鲜明：

on-policy 蒸馏仅 1,800 GPU 时
而 RL 要 17,920 GPU 时
全指标 ↑

（如 AIME'24 74.4 vs 67.6）
pass@64 ↑
蒸馏扩大探索空间
而 RL 的 pass@64 原地不动
最有意思的一点：RL 只能强化模型已经会的东西（pass@64 维持 90.0 / 83.3 不变），而蒸馏从教师 logits 学到了新东西——pass@64 升到 93.3 / 86.7。也就是说，蒸馏不只让学生「答得更稳」，还抬高了它的推理潜力上限。

一句话总结
先用 off-policy 蒸馏让小模型「会说话、会切模式」，再用 on-policy 蒸馏对齐 logits 把推理能力顶上去——性能更好、还便宜约 10 倍，并保留对推理过程的细粒度控制，省去为每个小模型单独跑四阶段的必要。
