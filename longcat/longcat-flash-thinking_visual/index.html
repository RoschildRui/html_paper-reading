⚡ TL;DR（30 秒看懂）

LongCat-Flash-Thinking 在已有的 560B MoE 基座（LongCat-Flash-Base）上，用一条「长 CoT 冷启动 → 大规模 RL」流水线把它训成顶尖开源推理模型，擅长数学、代码、逻辑与 Agentic 工具使用。

三个核心创新：① 分领域并行 RL + 专家融合——分别训练 STEM / Code / Agentic 专家，再合并成一个近 Pareto 最优的模型，避开混合训练的负迁移；② DORA 异步 RL 系统——流式异步 rollout + 弹性同机部署，比同步训练快 3 倍以上，可在数万张加速卡上稳定训练；③ 面向工具使用的高效推理——在 AIME-25 上把平均 token 从 19,653 砍到 6,965（省 64.5%）而精度不掉。

结果：在开源模型里取得多项 SOTA，形式化证明（MiniF2F pass@1 67.6%）与 Agentic 推理尤其领先。

01 · 问题

为什么还要再做一个推理模型？

从「会答题」到「会思考」，前沿模型的竞争已经转向推理能力本身。

近两年大模型的前沿明显往推理能力偏移：OpenAI o1/o3、Gemini 2.5、DeepSeek-R1、Qwen3、GLM-4.5 都在比谁能在数学、代码、复杂逻辑和 Agentic 任务上想得更深。背后的范式很统一——用大规模强化学习（RL）训练，让模型在推理时主动拉长思维链（Chain-of-Thought），把更多算力花在「想」上。

但要把这套范式做到工业规模、且开源可用，要同时啃下三块硬骨头：

  • 能力起点：基座模型的预训练语料里，长 CoT 这种「方法化推理」的样式天然稀缺，直接 RL 容易陷在同质化的推理套路里，遇到难题不会反思。
  • 训练稳定性：把数学、代码、Agentic 几个领域混在一起做 RL，不同领域的回答长度、分布差异巨大，异步训练时会互相拖累（负迁移）。
  • 系统效率：长推理 / 多轮工具调用让单条输出极长，同步 RL 的整个 batch 会被最长的那条卡住，数万卡的算力大量空转。

LongCat-Flash-Thinking 的目标，就是用一套数据、环境、算法、基础设施端到端协同设计的方案，把这三块一起解决。

02 · 已有方案卡在哪

三个「看起来能用、实际卡住」的做法

本文的三大贡献，几乎是逐一回应下面三个痛点。点击展开查看每种做法的瓶颈。

A
「SFT 之后直接 RL」→ 同质化推理
基座没补够长 CoT，模型遇难题不会深度反思
▶
通用基座→SFT→RL→推理套路单一

通用预训练语料里 STEM / 代码这类推理密集数据本就偏少，而显式的长 CoT 结构（一步步推演、回溯、自检）即便在这些数据里也很罕见。

结果是：哪怕后面再 SFT + RL，模型也容易产出同质化的推理模式，在真正难的题上无法深入反思、拿不到正解，推理边界（pass@k）被卡死。

本文的回应：先加一个mid-training「中期训练」阶段做课程式冷启动，专门拓宽推理边界（详见第 03 节）。

B
混合领域一起做 RL → 负迁移
不同领域回答分布差异大，异步训练互相拖累
▶
STEMCodeAgentic→ 混在一个 batch →分布漂移 / 负迁移

把多个领域的数据混进同一批 RL，由于各领域回答长度与分布差异巨大（论文 Figure 7 显示不同领域的回答长度分布明显不同），相邻训练 batch 之间会出现剧烈的分布漂移，在异步训练里表现为负迁移：学了一个领域反而拖累另一个。

退而求其次的顺序训练（一个领域训完再训下一个）虽能缓解，但效率低、不灵活，且一旦进入后期阶段就很难再回头打磨早期能力。

本文的回应：分领域并行训练 + 专家融合（详见第 03 节核心配方）。

C
同步 RL / 朴素部分 rollout → 算力空转
长尾生成阻塞批次；分段 rollout 又有重复 prefill 开销
▶
batch 内多条 rollout→被最长那条阻塞（其余卡空转）

同步训练下，整个 batch 必须等最长的那条输出生成完才能开训。推理 / Agentic 多轮调用让输出长度长尾严重，于是出现「偏斜生成（skewed generation）」——少数超长样本拖垮整批吞吐。

已有的部分 rollout（partial rollout）异步方案把长回答切段、用最新模型逐段续写，但实践中有两个问题：① 被打断样本需要重复 prefill，开销大；② 同一条回答的不同段来自不同策略版本，理论上会损害收敛。

本文的回应：DORA 系统——流式异步 + 多版本一致性 + KV-cache 复用 + 弹性同机部署（详见第 03 节）。

03 · 本文方法（重头戏）

一条流水线：长 CoT 冷启动 → 大规模 RL

先把「会推理的潜力」打底（冷启动），再用 RL 把潜力放大到极致——而 RL 的核心配方是「分领域并行 + 融合」。

整体训练分两大阶段。第一阶段长 CoT 冷启动（mid-training + SFT）为基座注入扎实的推理底子与形式化、Agentic 等专项技能；第二阶段大规模 RL则把潜力放大，并通过分领域并行训练得到多个领域专家、再融合。下图是全文最重要的一张总览图。

3.1 第一阶段：长 CoT 冷启动

冷启动的目标是把「会深度推理」的底子打好，分两步走：

  • Mid-training（中期训练）：把标准中期训练改造成一条平衡的课程，按比例注入推理密集数据。原文在小规模同架构模型上的对照实验显示，提高推理数据占比能稳定提升 pass@1～pass@128：AIME-24 的 pass@1 提升 27.7%、BeyondAIME 9.3%、LiveCodeBench 6.5%，且高 k 值提升更大——说明推理边界被真正拓宽了。
  • Reasoning-Oriented SFT：在三类数据上做监督微调（AdamW、lr=3e-5、2 epoch、48K 上下文），分别强化通用推理、形式化推理、Agentic 推理。

这三类 SFT 数据的合成尤其讲究——下图是冷启动的数据策展全景，其中左下、右下两个子流程是两个亮点。

🔍 形式化推理为何亮眼

大多数 LLM 几乎不会写形式化证明。本文用「自动形式化 + Lean4 验证 + 专家迭代」造出大量(命题, 思考过程, 已验证证明)三元组，把这种稀缺能力系统性地灌进模型——这也是它在 MiniF2F 上大幅领先的根源。

3.2 第二阶段：大规模 RL（系统 + 算法 + 奖励 三管齐下）

RL 是把推理能力放大的关键，但出了名的不稳定、对超参敏感、系统开销大。本文从三个层面同时下手：

① 系统层：DORA 异步 RL 框架

DORA（Dynamic ORchestration for Asynchronous rollout）的核心思路：用流式 rollout + 保留 Actor 的多个旧版本来消化长尾生成，同时让 RL 的各种角色弹性同机部署，把设备空转压到接近零。集群被切成两组：专职生成的 Standalone Generator Group，以及可在生成 / 训练角色间动态切换的 Elastic Role Group。

配合 DORA，工程上还有两个放大器：把控制面的 TCPStore 通信复杂度从 O(N²) 降到 O(N) 的大规模流式 RPC；以及用图级编译减少 kernel 分发、带来 1.5× rollout 提速的大规模 MoE 并行。整套系统让 RL 投入达到约预训练算力的 20%仍然可行。

② 算法层：为异步训练改造的 GRPO

异步训练会带来分布漂移，主要来自两处：推理引擎与训练引擎的数值差异（如 vLLM 的 kernel fusion 不保证逐位一致），以及策略陈旧（staleness）（样本来自多个旧版本策略）。本文在 GRPO 基础上做了四处关键修改：

  • 去掉 KL 损失项：默认 k₃ 估计器的梯度有偏，移除后更利于大幅度策略更新。
  • token 级损失 + 全局常数最大长度做分母：缓解长度偏置，稳住训练。
  • 三元裁剪（triplet clipping）：对负优势用 ε_neg_low / ε_neg_high 限幅、对正优势用 ε_pos_high 限幅——尤其在稀疏 MoE 里防止 importance ratio 爆炸导致崩溃。
  • 截断重要性采样：抑制推理/训练引擎数值差累积带来的失稳。

此外还有带放回的在线过滤（剔除全对/全错样本，保留有梯度信号的难样本）、陈旧度控制 + 回放缓冲、不完整信号掩码（屏蔽沙箱报错、超长截断等坏信号）等效率与稳定性技巧。

③ 奖励层：可验证 + 不可验证都覆盖

  • 不可验证任务（创意写作、知识问答）：用判别式奖励模型，只评估答案部分、不看推理过程。
  • STEM 等可验证任务：用带推理过程的生成式奖励模型（Reasoning GenRM），能识别 a²−b² 与 (a+b)(a−b) 这类等价表达。其判定准确率 98.8%，远高于规则奖励的 80.9% 和无推理 GenRM 的 94.0%。
  • 代码任务：分布式代码沙箱集群，支持 20+ 语言、百万级并发执行，异步接口 + 一次编译多次运行。

STEP 1 · 分领域并行训练（Domain-Parallel Training）

STEM RLCode RLAgentic RL → 各自得到一个领域专家

从同一个 SFT 模型出发，并行训练三个领域专家，且每个领域用最适配自己的配置：

  • STEM RL：固定 64K 上下文；按通过率门槛逐步加难（课程学习），并动态调整 PPO 上裁剪界保持稳定。
  • Code RL：上下文做多阶段课程，48K → 56K → 64K，当 90 分位输出长度逼近上限就扩窗。
  • Agentic RL：固定 48K；用 <longcat_think> / <longcat_tool_call> 结构化模板 + 工具调用格式奖励，保证多轮轨迹可解析。

为什么这么做：各领域回答长度/分布差异太大，混在一起会负迁移；并行 + 定制配置既高效又互不干扰。

STEP 2 · 专家融合（Model Fusion）

STEM 专家Code 专家Agentic 专家 → 参数合并 →单一融合模型

把三个专家的参数合并成一个模型，难点是化解专家之间的参数干扰。本文用三招组合：

  • 归一化（Normalization）：对各领域的任务向量 τ_i = θ_RL_i − θ_SFT 做幅度归一，平衡各方贡献。
  • Dropout（仿 DARE）：裁掉冗余的 delta 参数。
  • Erase（仿 SCE）：抹去方向上属于少数派的更新元素。

为什么这么做：已有研究表明，合并领域模型能得到整体更强的单一模型；这一步让模型在数学、代码、Agentic 上同时接近 Pareto 最优，而不是顾此失彼。

STEP 3 · 通用 RL 收尾（Final General RL）

融合模型+ 通用/合成数据 → PPO →LongCat-Flash-Thinking

最后一轮通用 RL，目标是提升广义场景能力并防止融合后核心能力回退：

  • 汇集开源 + 合成 query，用聚类去重过滤出高质量、有挑战性的数据。
  • 做一轮 PPO 训练，强化创意写作、指令遵循等通用能力。
  • 巩固安全与人类对齐，确保真实应用下稳健可用。

为什么这么做：融合可能让通用 / 安全等能力略有漂移，通用 RL 把整体能力「捏合」到位，得到最终交付模型。

04 · 有意思的点

几个反直觉或巧妙的设计

💡 让模型「学会偷懒」反而更强

在 Agentic 设置下，模型可以把部分推理步骤外包给外部工具而不是死磕纯文本长推理。结果在 AIME-25 上平均 token 从 19,653 降到 6,965（省 64.5%），而精度几乎不变——说明「靠工具高效推理」可以逼近「靠超长 CoT 暴力推理」的效果。

  • 用 vx 量化「工具必要性」：通过有/无工具两路的通过率之差，精准筛出「真正离不开工具」的训练题，避免模型不用工具也能蒙对的无效数据。
  • 奖励模型也要「会推理」：带推理过程的 GenRM 把 STEM 判定准确率从 80.9%（规则）拉到 98.8%，还能解释判定理由、便于持续改进。
  • 多版本一致性 > 分段最新：DORA 坚持「一条回答由同一策略版本生成」，宁可保留旧版本，也不让一条回答跨版本拼接——稳定性优先。

06 · 一句话总结

把「会思考」做成可工业化的工程问题

LongCat-Flash-Thinking 的价值不只在分数，而在于它把「训练推理能力」拆成了数据合成、RL 算法、奖励系统、训练基础设施四个可以分别攻克、又端到端协同的工程模块，并给出了一套「分领域并行 + 专家融合 + 异步 RL」的可复制配方。对想做大规模推理 RL 的团队，DORA 的异步设计与领域并行的思路尤其值得借鉴。

模型在 Agentic 推理上把平均 token 砍掉约 64.5% 仍保持精度，说明「更强的推理」不一定等于「更长的思考」，也可以是「更聪明地调用工具」。 "...reducing average token consumption by 64.5% on AIME-25, without degrading task accuracy."
