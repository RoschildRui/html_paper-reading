00 TL;DR · 30 秒抓住核心

  • 是什么：Kimi K2 是一个 1.04 万亿参数的 MoE（混合专家）大模型，每次只激活 320 亿参数，专门为「智能体能力」（工具使用、多步推理、软件工程）设计，并开源了基座与后训练权重。
  • 预训练怎么稳：用 token 效率更高的 Muon 优化器，但 Muon 放大规模时会「注意力 logit 爆炸」。本文提出 QK-Clip 直接给 Q/K 投影权重「剪枝」，合成 MuonClip，在 15.5 万亿 token 上训练全程零 loss 尖峰。
  • 数据怎么榨：高质量 token 不够用，于是用分块自回归改写把知识/数学语料安全地扩增；又用一条大规模智能体数据合成流水线（造工具→造 agent→造任务→造轨迹）批量造出可验证正确的工具使用样本。
  • 对齐怎么做：强化学习同时用可验证奖励（RLVR）（数学/代码/指令等有标准答案的任务）和自我批判 rubric 奖励（模型给自己的输出打分），把对齐从「有标准答案」延伸到「开放主观」任务。
  • 结果：在 non-thinking（不开思维链扩展）设定下，K2 是开源 SOTA，尤其在 编码与智能体工具使用 上逼近甚至反超闭源 Claude 4；LMSYS Arena 上是开源第一、总榜第五。

01 问题：通往「智能体」的两道坎

论文开篇就把基调定在一个范式转变上：大模型正从静态的模仿学习（学人类写好的文本）转向 Agentic Intelligence（智能体智能）——模型能在复杂、动态的环境里自主感知、规划、推理、行动，通过与环境交互获得训练分布之外的新技能。要达到这个目标，预训练和后训练各有一道坎：

坎一 · 预训练：token 不够「贵」
  • 高质量人类数据越来越稀缺，模型却越做越大
  • 于是 token 效率（每个 token 带来多少学习信号）成了扩展的关键系数
  • 简单地把数据重复多遍 → 过拟合、泛化变差
坎二 · 后训练：智能体数据太稀缺
  • 多步推理、长程规划、工具使用这些能力，在自然语料里几乎不存在
  • 真实环境能提供真信号，但构建成本高、难规模化（成本、复杂度、隐私、可达性）
  • 需要可规模化地合成结构化、高质量、可验证的智能体轨迹
本文要回答的问题
能不能既在预训练阶段把每个高质量 token 的价值榨到最大、还保证万亿规模训练稳定，又在后训练阶段大规模造出真实可用的工具使用数据，并用一套强化学习框架把这些能力从「有标准答案」延伸到「开放主观」的任务上？

02 已有方案卡在哪

K2 的每一项设计都是针对一个具体的「已有方案不够好」。先建立画面感——下面四张卡片就是本文方法的「反面动机」，点开看它们各自卡在哪：

⚙️AdamW 优化器 主流基线
几乎所有大模型默认的优化器，稳定但token 效率不够高。
展开说明 ▸

做法：逐参数自适应学习率的一阶优化器，工程成熟、训练稳定。

卡在哪：在相同算力与数据下，学到的东西不如 Muon 多。当高质量 token 成为稀缺资源时，token 效率不足就是硬伤。

与本文关系：K2 改用 Muon 来提升 token 效率——这又引出了下一个问题。

🚀Muon 优化器 高效但不稳
月之暗面前作验证过：同等算力下 Muon 明显优于 AdamW，但放大规模会训练不稳。
展开说明 ▸

做法：对权重更新做正交化（近似），让更新矩阵的奇异值更均匀，token 效率更高。

卡在哪：放大规模时注意力 logit 会爆炸（attention logits explosion），引发 loss 尖峰甚至训练发散——这个现象在 Muon 上比 AdamW 频繁得多。

与本文关系：本文要的是 Muon 的效率 + 稳定性，于是发明 QK-Clip 来「驯服」它。

✂️既有的稳定手段 不够用
logit soft-cap、QK-Norm 这些常见招数，对 K2 的场景都不适用。
展开说明 ▸

logit soft-cap：直接给注意力 logit 封顶，但 Q·K 点积在封顶前就可能已经涨得过大，治标不治本。

QK-Norm：对 Q、K 做归一化，但它不适用于 MLA（多头潜在注意力），因为 MLA 的 Key 矩阵在推理时并不完整物化。

与本文关系：两条路都被堵死，所以本文从「权重」下手，提出新的 QK-Clip。

🌍靠真实环境收集智能体数据 难规模化
让 agent 在真实系统里跑、收集轨迹，信号真但太贵、太难铺开。
展开说明 ▸

做法：搭建真实工具/环境，让模型在其中交互，记录工具调用轨迹做训练数据。

卡在哪：真实环境受成本、复杂度、隐私、可达性限制，很难造出足够多样、足够多的高质量轨迹。

与本文关系：本文转向「大规模模拟合成 + 关键场景真实沙箱」的混合路线，兼顾覆盖面与真实性。

03 方法总览：预训练求「稳与省」，后训练求「会干活」

K2 的整套方法可以挂在一条主线上：token 效率（token efficiency）。预训练阶段想方设法让每个 token 学到更多、还要训得稳；后训练阶段则把这些「通用先验」转化成「真能动手」的智能体行为。下面两条产线各管一头：

① 预训练 Pre-training 稳定 + 高 token 效率
在有限高质量数据下，把每个 token 的学习价值榨到最大，并保证万亿规模训练全程不崩。三件套：
MuonClip 优化器（稳定 + 高效） 数据改写（提升 token 价值） 超稀疏 MoE 架构（scaling law 调出来的）
② 后训练 Post-training 把先验变成智能体行为
让模型真正学会用工具、对齐人类偏好。两件套：
大规模智能体数据合成（SFT 教会工具使用） 统一 RL 框架（可验证奖励 + 自我批判）

下面我们按「MuonClip → 数据改写 → MoE 架构（预训练三件套）→ 智能体数据合成 → RL 框架（后训练两件套）」的顺序逐一展开，方法部分是全文重头戏。

04 MuonClip：让高效的 Muon 也能稳稳训到万亿规模

这是预训练的第一件武器。逻辑链很清晰：Muon 效率高 → 但放大会 logit 爆炸 → 用 QK-Clip 从权重侧摁住 → 合成 MuonClip。

为什么 Muon 会「注意力 logit 爆炸」

注意力分数（softmax 之前的输入）本质是 q·k 的点积。训练中如果 Q、K 投影权重的谱范数（最大奇异值）不断变大，这个点积就会无界增长，最终触发数值不稳定、loss 尖峰乃至发散。论文在附录给出了假设：Muon 的更新矩阵奇异值更均匀、有效秩更高（不像 Adam 那样被少数大奇异值主导），更容易让权重的奇异值叠加式增大；而注意力的双线性形式 QᵀK 又把谱范数平方放大，于是 Muon 更容易 logit 爆炸。

QK-Clip：不动前向计算，只在事后给权重「剪一刀」

QK-Clip 的核心想法极简：每一步训练后，监控每个注意力头的最大 logit；只要它超过阈值 τ，就把这个头的 Q、K 投影权重按比例缩小，把 logit 拉回阈值以下。几个关键设计：

  • 不改当前步的前向/反向：最大 logit 只作为「该收多紧」的指示信号，缩放发生在更新之后，不污染本步梯度。
  • 逐头（per-head）而非逐层：实际只有极少数头会爆炸，逐头处理把干预降到最小，不连累其它正常的头。
  • 适配 MLA：对多头潜在注意力，只缩放每个头独有的 Q/K 分量（含 head-specific 的旋转位置部分），共享的旋转分量保持不动，避免跨头副作用。
若 max_logit(head) > τ ：  Wq, Wk ← Wq·√(τ/max_logit),   Wk·√(τ/max_logit)
把超阈值那一头的查询/键投影权重各乘一个 <1 的因子，等比例把 logit 压回 τ 以内（K2 取 τ = 100）。

MuonClip 就是把「Muon + 权重衰减 + 一致的更新 RMS 缩放 + QK-Clip」打包进一个优化器。下面两张图是它有效性的最直接证据。

图 2（原论文 Figure 2）：左图为中等规模（9B 激活 / 53B 总参）只用原始 Muon 的训练，最大注意力 logit 急剧爆炸；右图为 K2 用 MuonClip，logit 被 QK-Clip 牢牢压在阈值 τ=100 内并随训练自然衰减。

  • 两图对比：同一个「logit 爆炸」问题，左边任其发展会炸，右边被 QK-Clip 稳稳摁住——这正是 MuonClip 把「会发散的训练」变成「全程平稳」的可视化证据。

一句话总结：左图是病，右图是药；QK-Clip 在不牺牲 Muon 效率的前提下，把注意力动态稳稳控制住。

图 3（原论文 Figure 3）：K2 全程逐步训练 loss（未平滑、未下采样），从 0 到 15.5 万亿 token 平滑下降、没有一个尖峰。
展开说明 ▸
  • 横轴：已消耗的训练 token 数（0 到约 15.5 万亿）。纵轴：训练 loss（约 1.3–2.0）。
  • 蓝色曲线：K2 的逐步训练 loss，没有做任何平滑或下采样，所以看得到真实噪声。
  • 蓝色「带宽」：是逐步训练的自然抖动，不是尖峰；真正的 loss 尖峰会表现为突然向上的孤立高峰，这条曲线上一个都没有。
  • 为什么难：在 1 万亿参数、15.5 万亿 token 的规模上做到「零尖峰」极难——大模型训练里一个尖峰就可能要回滚 checkpoint、损失大量算力。
  • 结论：这条曲线就是摘要里「zero loss spike」的实证，说明 MuonClip 对超大规模训练提供了鲁棒、可扩展的稳定性。

一句话总结：「零 loss 尖峰」不是口号，这条平滑曲线就是 MuonClip 让万亿训练可控的证据。

▸细节：QK-Clip 会不会损害模型质量？它会一直开着吗？点开看小规模消融 + 自动失活现象

不损害质量：论文训了两个 0.5B 激活 / 3B 总参的小模型对照，一个用原始 Muon、一个用带激进低阈值的 MuonClip。结果 loss 曲线几乎重合，下游任务也无统计显著退化——说明即使「剪得很狠」也不伤收敛（见原论文 Figure 12）。

会自动失活（self-deactivation）：在 K2 训练中，QK-Clip 只是阶段性起作用——前 7 万步有一部分注意力头触发过 clip；7 万步之后所有头的最大 logit 都自然降到了阈值以下，QK-Clip 就不再生效了（这正对应图 2 右侧蓝线先触顶、后回落的形状）。它遵循「最小干预」原则：需要时才动手，稳定后自动退场。

05 数据改写：把同一份好语料，安全地「学好几遍」

这是预训练的第二件武器，目标还是 token 效率。难题是：高质量知识类文本，读一遍不够吸收，读很多遍又会过拟合。K2 的解法不是简单重复，而是用一个改写（rephrasing）流水线，把同一份内容用不同风格、不同视角重写多份，等于在不破坏事实的前提下「换着说法」多学几遍。知识领域的改写有三个关键组件：

  • 风格与视角多样化提示（受 WRAP 启发）：用一组精心设计的提示，引导一个 LLM 在保持事实正确的前提下，以不同文体、不同视角忠实改写原文。
  • 分块自回归生成：长文先切块、逐块改写、再拼回，突破 LLM 的隐性输出长度上限，同时保持全篇连贯（见下图）。
  • 保真度校验：改写后与原文做语义一致性比对，作为进入训练前的初步质量闸门。
图 4（原论文 Figure 4）：面向长文的「分块自回归改写」流水线——切块（保留上下文）→ 逐块改写 → 拼接成完整改写段落。
展开说明 ▸
  • 输入（蓝，左上）：一段最长约 4096 token 的高质量原文（full input excerpt）。
  • split（切块）：原文被切成若干约 256 token 的小块（partial input excerpt 1、2、…），避免一次性改写长文时的信息丢失与长度限制。
  • rewrite model（紫，改写模型）：逐块改写；改写下一块时，把上一块的改写结果作为上文（auto-regressive，图中向下的「auto-regressive」箭头），保证全篇风格、指代、逻辑连贯。
  • partial output excerpt（绿，右）：每个小块对应的改写结果。
  • concat（拼接，右上）：把各块改写结果拼接回完整的改写段落（full output excerpt）。

一句话总结：这条流水线把「读很多遍同一份原文」换成「读这份原文的多个忠实改写版」，提高 token 价值又不至于过拟合。

数学领域则把高质量材料改写成「学习笔记」风格（参考 SwallowMath），并把其它语言的优质数学资料翻译成英文以增加多样性。改写到底有没有用？论文用 SimpleQA 做了一个干净的对照实验：

训练策略改写次数训练轮数（epoch）SimpleQA 准确率
原始数据重复多遍0（原始 wiki 文本）1023.76

06 MoE 架构：用 scaling law 调出来的「极致稀疏」

第三件武器是模型结构本身。K2 整体沿用 DeepSeek-V3 风格——超稀疏 MoE + 多头潜在注意力（MLA），但在两个关键超参上做了和 scaling law 实验相符的取舍：专家更多（更稀疏）、注意力头更少。

更稀疏 = 更强：稀疏度 scaling law

「稀疏度」= 总专家数 / 激活专家数。论文做了一组控制实验：在固定激活参数（即固定 FLOPs）下，增加总专家数能持续降低训练与验证 loss。最终 K2 选了稀疏度 48——384 个专家里每次只激活 8 个（外加 1 个共享专家）。

图 5（原论文 Figure 5）：稀疏度 scaling law——固定激活专家为 8，提高总专家数（提高稀疏度），在相同算力下验证 loss 更低。
展开说明 ▸
  • 横轴：训练 FLOPs（对数坐标）。纵轴：验证 loss（越低越好）。
  • 五种颜色：稀疏度 8 / 16 / 32 / 48 / 64，激活专家数固定为 8，只改变总专家数。
  • 每条彩色虚线：对应稀疏度的「计算最优」前沿；图中红色星标是各档的最优配置点。
  • 读图重点：在相同 FLOPs 下，越稀疏（48 绿、64 蓝）验证 loss 越低，即同样算力能得到更强模型。
  • 量化收益：要达到相同验证 loss 1.5，稀疏度 48 相比稀疏度 8 / 16 / 32 分别省下 1.69× / 1.39× / 1.15× 算力。继续提稀疏度还能更好，但会推高工程复杂度，于是 K2 权衡后选 48。

一句话总结：这张图是「为什么 K2 用 384 个专家」的直接依据——稀疏是免费的午餐，只是要付工程的账。

更少注意力头：为长上下文与智能体场景让路

DeepSeek-V3 把注意力头数设成约层数的两倍以提升带宽利用，但长上下文下这会大幅推高推理开销。论文实测：序列长 128k 时，把头数从 64 提到 128（专家数不变）会让推理 FLOPs 暴涨 83%，而验证 loss 只改善 0.5%–1.2%。对重度依赖长上下文的智能体应用，这笔账不划算，于是 K2 把注意力头砍到 64。

07 智能体数据合成：批量「造」出工具使用轨迹

进入后训练。要教会模型用工具，就得有海量「工具使用轨迹」做监督微调（SFT）。但真实环境难规模化（见第 02 节），所以 K2 搭了一条三阶段合成流水线，受 ACEBench 启发，能批量产出多样、可验证正确的工具使用样本。点「下一步」跟着流水线走一遍：

STAGE 1造工具：构建工具库（Tool Repository）
两条腿走路：① 从 GitHub 直接抓取 3000+ 个真实 MCP 工具（Model Context Protocol，复用已有高质量工具规范）；② 通过层级化领域演化——先定大类（金融交易、软件应用、机器人控制…），再演化出具体应用领域，为每个领域合成带清晰接口/描述/语义的工具，共造出 20000+ 个合成工具。t-SNE 可视化显示真实工具与合成工具覆盖了互补的区域。
输入
GitHub 真实 MCP 工具 + 领域大类种子
输出
真实 + 合成工具组成的统一工具库
STAGE 2造 agent 与任务（Agent & Task）
从工具库里采样不同的工具子集，配上各异的系统提示，生成数千个不同的 agent（能力、专长、行为风格各异）。再为每个 agent 配置生成从简单到复杂的任务；每个任务都附带一份显式 rubric（评分标准），写明成功条件、预期的工具调用模式与评估检查点——让后续评估客观一致。
输入
工具库 + 系统提示模板
输出
数千个 agent + 带 rubric 的任务
STAGE 3造轨迹并筛选（Trajectory & Filter）
模拟真实多轮交互：用户模拟器（不同沟通风格的 LLM 用户）与 agent 多轮对话；工具执行环境（相当于一个 world model）执行工具调用、维护状态、返回带受控随机性的反馈（成功 / 部分失败 / 边界情况）。完整轨迹交给 LLM 裁判按任务 rubric 评估，只保留达标的轨迹——本质是一次大规模拒绝采样。
输入
agent + 任务 + 用户模拟器 + 工具模拟器
输出
经 rubric 筛选的高质量工具使用轨迹

论文用两张图分别画出了前两步（造工具/agent/任务）和第三步（造轨迹/筛选）：

图 8a（原论文 Figure 8 上）：上游——「造工具 → 造 agent → 造任务」。
展开说明 ▸
  • Domains → Applications：从领域大类层级演化出具体应用领域，作为合成工具的「土壤」。
  • MCP tools → real-world tool specs：从 GitHub 抓取的 3000+ 真实 MCP 工具，转成真实工具规范。
  • Applications → synthesized tool specs：为每个演化出的应用领域合成 20000+ 个带接口/描述/语义的工具规范。
  • Tool Repository（浅蓝框）：真实工具规范 + 合成工具规范汇成统一工具库。
  • → Agents → Tasks with rubrics：从工具库采样工具子集生成多样 agent；再为每个 agent 生成带评分标准（rubric）的任务。

一句话总结：这是合成流水线的上游，先把「舞台（工具）、角色（agent）、剧本（带 rubric 的任务）」批量搭好。

图 8b（原论文 Figure 8 下）：下游——「造轨迹 → 按 rubric 筛选」。左侧虚线框是模拟交互闭环，右侧是质量筛选。
展开说明 ▸
  • Task → User Agent：任务驱动一个 LLM 模拟的「用户」，带有不同的沟通风格与偏好。
  • User Agent ⇄ Agent（interaction）：模拟用户与待训练 agent 进行多轮对话。
  • Agent ⇄ Tool Simulator（call / observation）：agent 发起工具调用（call），工具模拟器（相当于 world model）维护状态、返回带受控随机性的真实反馈（observation），覆盖成功、部分失败、边界情况。
  • trajectories → Judge Agent（+Rubrics）：完整交互轨迹连同任务 rubric 一起交给裁判模型评估。
  • → Filtered Data：只有满足成功标准的轨迹被保留为训练数据，等价于大规模拒绝采样。

一句话总结：左框「模拟真实工具使用」负责覆盖面，右侧「按 rubric 筛选」负责质量——量与质同时拿到。

模拟 + 真实：混合方案补上「保真度」
纯模拟有覆盖面但保真度有限。对编码与软件工程这类真实性至关重要的场景，K2 额外接入真实执行沙箱：跑真实代码、对接真实开发环境，用单元测试通过率等客观指标提供 ground-truth 反馈。这套沙箱基于 Kubernetes，可同时跑 10000+ 个沙箱实例。

08 RL 框架：可验证奖励 + 让模型「自己当裁判」

后训练的第二件武器是强化学习。论文认为 RL 比 SFT 有更好的 token 效率与泛化，于是在 K1.5 基础上继续把 RL 在任务多样性与训练算力两个维度同时放大。框架是一个 Gym 式可扩展系统，核心分两块：能自动判对错的任务用「可验证奖励」，主观开放的任务用「自我批判」。

第一块：可验证奖励 Gym（Verifiable Rewards Gym）

凡是能自动验证对错的任务，都被纳入一个统一的「健身房」里训练。覆盖五大类：

DOMAIN 1
数学 / STEM / 逻辑
原则是覆盖多样 + 难度适中：用标注/抽取/开源数据收集 QA，并按 SFT 模型的 pass@k 难度只挑不太易也不太难的题，保证学习信号。
DOMAIN 2
复杂指令遵循
双路验证：能自动判的用代码解释器判（长度/风格等），需理解的用 LLM 裁判判；再加一层 hack-check 专抓「假装完成」的作弊。
DOMAIN 3
忠实性 Faithfulness
训练一个句子级忠实性裁判（受 FACTS Grounding 启发），检测「没有上下文支撑的事实声明」，作为奖励模型提升忠实度。
DOMAIN 4
编码 & 软件工程
竞赛题用高质量人写单元测试判分；SWE 任务从 GitHub 的 PR/issue 构建可执行环境，跑在能并发 10000+ 沙箱的 K8s 上。
DOMAIN 5
安全 Safety
从人工种子提示出发，用攻击模型 / 目标模型 / 裁判模型的自动演化流水线模拟越狱，按 rubric 给二元成功/失败标签。
关键思想
凡可验证，皆可 RL
把「对错可自动判定」的任务统统标准化进 Gym，奖励客观、可规模化、难作弊——这是整套 RL 的稳固地基。

第二块：自我批判 rubric 奖励（Self-Critique Rubric Reward）

但创意写作、开放问答这类没有标准答案的任务怎么办？K2 的答案是让模型给自己打分：同一个 K2 既当「演员（actor）」生成回答，又当「评论家（critic）」对自己的多个输出做成对比较排名，产生偏好信号去更新策略。

① Actor 生成
K2 actor 对各类开放 prompt 生成多个候选回答。
→
② Critic 成对评判
K2 critic 按一组 rubric（核心价值观 + 防作弊 + 人工标注）对回答两两比较、排名。
→
③ 偏好信号
排名转成偏好奖励，更新 actor 策略，对齐有用性、创意、深度、事实性、安全等。
→
④ Critic 自我校准
用可验证任务（RLVR）的客观信号持续 refine critic，把「会判对错」的能力迁移到「判好坏」。
🔁 闭环关键（Closed-Loop Critic Refinement）：critic 不是固定的——它用可验证奖励的 on-policy rollout 不断重新校准自己的评判标准，让「客观对错」的能力源源不断地为「主观好坏」的判断兜底。这样就把对齐从「有标准答案」稳稳延伸到「开放主观」。

RL 算法的三处加料

把 RL 扩到这么多任务，关键挑战是「各域都要稳步提升」。论文在 K1.5 的策略优化（用 Muon 优化）之上加了三招：

💰预算控制 Budget Control
给每个样本设按任务类型而定的最大 token 预算，超了就截断并罚分。
展开说明 ▸

RL 常让回答越写越长，但在非推理任务上「更长」不值它的推理成本。强制预算逼模型把算力花在刀刃上，显著提升 token 效率、鼓励简洁有效的解。

📌PTX 损失 PTX Loss
把一批精选高质量数据作为辅助损失混进 RL，防止遗忘。
展开说明 ▸

联合 RL 容易把预训练学到的宝贵数据「训没了」。PTX 辅助损失既保住高质量数据，又缓解只对少数 RL 任务过拟合，提升跨域泛化。

🌡️温度衰减 Temperature Decay
前期高温多探索，后期降温多利用。
展开说明 ▸

创意写作、复杂推理在训练早期需要高采样温度来发现多样策略、避免过早收敛；但后期/评估时高温会引入过多随机性、损害可靠性。温度按计划从探索过渡到利用。

⚡RL 基础设施：30 秒换权重
训练/推理引擎 colocate，靠 checkpoint engine 极速同步参数。
展开说明 ▸

1T 模型每轮 RL 都要把新参数从训练引擎搬到推理引擎。K2 用分布式 checkpoint engine 逐参数流水线广播，不到 30 秒就能完成一次全量参数更新，对一次 RL 迭代几乎可忽略；代码已开源（见图 10）。

图 10（原论文 Figure 10）：用 checkpoint engine 做参数更新——训练、检查点、推理三类引擎共置（colocate），通过广播在 30 秒内完成 1T 模型的全量参数同步。
展开说明 ▸
  • pod（外框）：训练、检查点、推理三类引擎共置在同一批机器上，一方工作时另一方释放/卸载 GPU 资源。
  • train engine（绿，train）：RL 训练引擎；rollout 时其参数被卸载到 DRAM。
  • train → ckpt：每个 checkpoint engine worker 先从训练引擎拿到一份本地参数副本。
  • broadcast（底部箭头）：checkpoint engine 各 worker 之间把完整参数集广播到全集群。
  • ckpt → inference（橙，inference）：推理引擎只取自己需要的参数分片。整体设计让训练/推理引擎完全解耦，便于维护、测试与容错。

一句话总结：这套「广播全量、各取所需」的设计牺牲一点带宽换来极简、解耦，把 1T 模型的参数同步压到 30 秒内。

09 有意思的点

除了主线，有几处贯穿全文的取舍与发现值得单独拎出来——它们往往比 benchmark 数字更能说明这份报告的「设计哲学」。

🎯一切围绕「token 效率」
MuonClip、数据改写、超稀疏 MoE——三件预训练武器其实是同一个目标的三个侧面。
展开说明 ▸

当高质量数据见顶，「每个 token 学到多少」成了 scaling 的真正瓶颈。Muon 提升单 token 学习量、改写 让同份内容产生更多有效学习信号、稀疏 MoE 在固定 FLOPs 下榨出更低 loss——本质都在抬高 token 的「单位价值」。

🪞让客观能力为主观判断兜底
self-critique 的闭环里，critic 用「可验证对错」的信号持续校准「主观好坏」的评判。
展开说明 ▸

纯靠模型给自己打分很容易「奖励作弊」、自我陶醉。K2 的巧思是：把 RLVR 里学到的客观判断力，源源不断地蒸馏进 critic，让它在评判创意写作这类主观任务时也有「客观地基」。这是把对齐从可验证域扩到开放域的关键。

⏳QK-Clip 的「最小干预 + 自动退场」
只在需要时对个别头出手，训练稳定后自动失活，几乎不留副作用。
展开说明 ▸

QK-Clip 逐头触发、不动前向计算；K2 训练里它只在前 7 万步对部分头起作用，之后全部头都自然降到阈值下、QK-Clip 彻底不生效。小规模消融也证明它对收敛与下游无显著损害——一个「该出手时才出手」的克制设计。

🧪合成数据，但承认它的边界
论文大量用合成数据，却也明确说这仍是「开放问题」。
展开说明 ▸

知识改写每份语料最多改 2 次，并强调跨域泛化、控幻觉、控毒性、保真与可规模化都还没完全解决。智能体数据也靠「模拟 + 真实沙箱」混合来补保真度。坦诚地标出边界，比只报喜更可信。

11 局限与小结

论文坦诚列出了 K2 当前的短板（这些往往比成绩单更能帮你判断它适不适合你的场景）：

  • 难题/工具定义不清时会「话痨」：面对硬推理或定义模糊的工具时，模型可能生成过多 token，导致输出被截断或工具调用不完整。
  • 不必要地开工具反而掉点：如果在用不到工具的任务上仍启用工具使用，某些任务表现会下降。
  • 一次性建整个项目不如「智能体框架」内跑：构建完整软件项目时，one-shot 提示的成功率不如把 K2 放进一个 agentic coding 框架里逐步完成。
这份报告最值得记住的一句话
要把大模型推向「智能体智能」，预训练要把 token 效率与稳定性同时拉满（MuonClip + 改写 + 稀疏 MoE），后训练要把稀缺的工具使用能力大规模合成出来，再用「可验证奖励 + 自我批判」把对齐从有标准答案延伸到开放主观——K2 用一个开源的万亿模型，把这条路走通并交了一份漂亮的 agentic 成绩单。
