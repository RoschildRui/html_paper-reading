# 处理「模型卡 / 技术报告」类论文

有一类论文既不是「单方法论文」，也不是「综述」，而是**模型技术报告 / model card**（如 Seed2.0、Qwen、DeepSeek、GLM、Kimi、MiniMax、Hunyuan 等的发布报告）。它们的结构和阅读重点都不同，套「问题→方法→实验」的常规叙事会跑偏。识别信号：标题含 “Model Card / Technical Report”；作者是某公司团队而非个人；正文以「能力维度 + 大量 benchmark 表 + 用例」组织，没有单一新方法。

## 叙事主线（替代常规论文主线）

```
这个模型/系列想解决什么真实问题（设计哲学）
  → 它的评测/能力框架是什么（这才是报告真正的「贡献」，不是某个结构）
  → 强在哪、诚实的差距在哪（选择性讲，别搬表）
  → 真实用例：模型到底能做成什么样的活（报告最有价值的部分）
  → 定位与结论
```

关键判断：**报告的「方法贡献」往往是它的评测体系 / 能力分类，而不是模型结构**（结构细节通常不公开）。把评测框架做成 taxonomy 可视化，是这类页面的骨架。

## 三个最容易踩的坑

1. **搬 benchmark 表**。技术报告动辄十几张大表、上百个 benchmark。绝对不要搬。做法：只挑 3–5 个 headline 数字做 metric card，再用一个「强项 vs 诚实差距」双栏 panel 概括定位。读者要的是「它站在什么位置」，不是逐格数字。
2. **忽略用例（use cases）**。这是技术报告里信息密度最高、最能让读者「看懂能力边界」的部分（真实 agent 轨迹：修 bug、GUI 操作、科学计算、证明）。用例数量多（常 10+），必须用**默认折叠的深度卡片**承载，折叠态给一行通俗摘要 + 场景 tag，不要平铺成长卷。
3. **只报喜不报忧**。好的技术报告会诚实标注局限（幻觉 PDF 条目、漏掉某机制、某约束数超阈值就崩）。这些「诚实的差距」对选型读者比分数更有用，务必保留并显眼呈现（可用 note 框 / gap 栏）。

## 用例卡片的内容配方

每张用例深度卡片（展开态）建议包含：
- **任务**：一两句说清要干什么、难在哪
- **模型的做法**：具体的技术动作（用了什么算法/策略、几轮完成、怎么定位根因）——这是「看懂」的关键，别只写「成功完成了 X」
- **为什么值得说 / 局限**：它和参考解法的区别，或诚实的短板

超过 5 行的运行示例（代码、交互日志、input-output）放进 `<details>`，折叠态一句话说明示例展示了什么。

## 一个好用的「视觉锚点」：自纠错 / 控制回路步进

技术报告里常出现「agent 在噪声反馈下自我纠错」的轨迹（GUI 误触、编译失败、测试不过 → 诊断 → 修正 → 重试）。这是**真实状态迁移**，非常适合做「下一步」步进动画：发出动作 → 观察结果 → 自省诊断 → 定向纠正 → 重锚定不变量 → 校验收束。比静态图更能传达「在线控制回路」的意味。（实现：CSS `.on` class 切换 + 一个 `loopStep(±1)` 函数，纯 JS，见 Seed2.0 页面 `#loopStepper`。）

## 取图：arXiv HTML 404 时的 PDF 兜底

新论文（尤其 2026 年的）常常**没有 arXiv HTML 版**（`/html/<id>v<ver>/` 返回 404），无法按常规从 `<img>` 取图。且这类报告的「图」多是密密麻麻的轨迹截图，信息价值低、不适合直接嵌。兜底策略：

- 用 `pypdf` 提取全文文本理清结构与数字：
  ```python
  from pypdf import PdfReader
  r = PdfReader('paper.pdf')
  text = '\n'.join((p.extract_text() or '') for p in r.pages)
  ```
- 需要图里的**具体数据**（如饼图占比）时，用 macOS `Read` 工具直接看 PDF 页或用 `pdfimages`/渲染单页为 PNG 提取那一张图，读出数值，**再用干净的 CSS 柱状图重画**（对齐单一 accent，不要嵌多色饼图——违反配色克制原则）。
- 轨迹类截图一律**重构成干净的 flow / stepper**，别嵌原始截图。

## 校验注意

- 数字全部逐个对回 PDF 提取文本的对应行（技术报告表格密集，最容易张冠李戴：看清楚列顺序，如 “GPT / Sonnet / Opus / Gemini / Seed” 的排列）。
- 浏览器扩展不可用时的运行时兜底：`node --check` 抽出的 `<script>` 验证 JS 语法；核对 `getElementById` / `querySelectorAll` 目标 DOM 数量（如步进的 stage 数 == dot 数，卡片数 == onclick 数）。
